# 히어로 디자인 시안

2026-10-28에 첫 화면을 'Coming Soon' 후킹으로 여는 구조로 바꾸면서 만든 시안이다. 시안은 HTML 목업이며 폰트는 CDN에서 불러온다. 실제 구현은 2단계에서 Next.js 컴포넌트로 했고, 값은 `src/styles/tokens.css`의 토큰을 쓴다.

| 파일 | 내용 |
| --- | --- |
| `hero-b.html`, `hero-b-*.png` | **확정안(B안, 청첩장 느낌)**. 2단계 구현의 기준 |
| `hero-a.html`, `hero-a-*.png` | 비교용 A안(전체 주황 글자, 입장권 스티커) |
| `hero-compare.png` | 두 안의 첫 화면 비교 |

## B안 구성

위에서 아래로 날짜 줄, 후킹, H1, 보조 문장, CTA, 영상 섹션 순서다.

- 날짜 줄: 가는 선 두 줄 사이에 반짝임과 '2026.12.25 정식 오픈'(`--ink-900`)을 둔다. 청첩장의 날짜 줄 느낌이다.
- 후킹: 가는 'Coming'(Pretendard 300, `--ink-900`)과 굵은 'Soon'(Pretendard 900, `--brand`)을 `--fs-display`로 쓴다. 데스크톱은 한 줄, 1024px 미만은 두 줄이다.
- 'Soon'의 oo는 흰자와 눈동자가 있는 두 눈이고 아래 영상을 내려다본다. 'Coming'의 i 점은 반짝임이다.
- D-day는 `--brand-deep` 왁스 실링 스티커('오픈까지 / D-58', 흰 글자 4.70:1)다. 데스크톱은 'n'의 오른쪽 위 어깨에, 1024px 미만은 'n' 옆에 붙는다. 실링 폭은 후킹 글자의 0.84배(1024px부터 0.72배)이고 `--seal-min`(68px)보다 작아지지 않는다.
- 히어로 높이는 `calc(100svh - var(--peek))`이고 내용은 세로 가운데에 놓인다. 기준 화면(1440×900, 390×844)에서 영상 섹션 윗부분이 첫 화면 아래에 보인다. 낮은 화면에서는 아래 13번을 따른다.

## 2단계 반영 결과

심사 두 곳(브랜드·후킹, 접근성·성능·구현)과 직접 검토에서 나온 13개 항목을 2026-10-29에 아래처럼 반영했다. 코드는 `src/components/Hero.tsx`, `Film.tsx`, `SoundBuddy.tsx`와 `src/styles/hero.css`, `film.css`, `buddy.css`에 있다.

| 항목 | 반영 |
| --- | --- |
| 1. 1024px 미만에서 실링이 'n'을 가림 | 실링을 'n' 옆(오른쪽 0.02em 밖)으로 옮겼다. 'Soon'과 실링을 한 덩어리로 가운데에 둔다. 실링 윗변은 시안처럼 'Soon' 줄 위에서 0.1em 내려와 'Coming'의 'g' 꼬리를 가리지 않는다 |
| 2. 1024~1199px에서 반짝임 겹침, 실링이 여백 밖으로 나감 | 떠 있는 반짝임을 후킹 글자 기준(em)으로 놓았다. 1024px부터 후킹 크기를 화면 폭으로도 제한해(`(100vw - 2 × 여백) / 6.9`) 실링이 여백 안에 든다 |
| 3. 사운드 버디 말풍선 | 첫 방문 2초 뒤 '소리 켜 볼까요?'를 6초 보인다. 세션마다 한 번이고, 소리를 켜면 사라진다. 소리 있는 소개 영상 파일이 오기 전에는 켤 소리가 없어 버디와 말풍선을 그리지 않는다 |
| 4. 반복 모션 줄이기 | 눈 깜빡임 5회, 반짝임 5회, 실링 흔들림 8회로 정하고, 후킹이 화면 밖이면 멈췄다가 돌아오면 다시 시작한다. 'Soon'의 상하 흔들림과 재생 버튼의 펄스 링은 뺐다. 무한 반복은 사운드 버디뿐이다. 5초를 넘는 자동 반복의 WCAG 2.2.2 처리는 `docs/OPEN_ITEMS.md` 6번(`motion-222`)에서 정한다 |
| 5. iOS 15.4 대체값 | 지원 하한을 iOS·Safari 16.4로 올려(기획서 v1.2) `cqw`와 `color-mix()`를 그대로 쓴다 |
| 6. 소개 정의 문장의 줄바꿈 | 3단계 소개 섹션에서 반영한다. 히어로 보조 문장은 쉼표로 나눈 구절을 한 줄로 묶었다 |
| 7. 제목과 설명 | `SITE.title`, `SITE.description`을 쓴다(1단계) |
| 8. 웹폰트 대기 | 글꼴이 준비되면(최대 700ms) 글자가 24px 아래에서 올라온다. 글자는 처음부터 보이고(LCP) 이동만 한다. 대기는 Hero가 HTML에 넣은 짧은 스크립트가 맡아 JS 번들이 늦거나 실패해도 글자가 제자리에 오고 실링이 보인다. 낮은 화면에서 LCP 후보가 되는 H1도 이동만 한다 |
| 9. `navigator.webdriver` 분기 | 넣지 않았다 |
| 10. 글로우 대비 | 글로우를 위쪽 `--glow-h`(220~300px) 안에서 끝냈다. 'Soon'은 크림 바탕(3.10:1) 위에 놓인다. 실링 그림자는 오른쪽 아래로만 지는 `--shadow-seal`로 바꿔 'n' 옆 크림을 물들이지 않는다. 실링 안 밝은 `--brand`는 왼쪽 위 가장자리(그라데이션 0~15%)에만 두어 라벨 밑은 `--brand-deep`(4.70:1)이다 |
| 11. 'zz' 위치 | 왼쪽 위로 떠오르고, 말풍선·툴팁이 보이는 동안 숨는다 |
| 12. A안에서 가져온 것 | 눈이 키보드 포커스를 받은 CTA와 켜진 버디를 쳐다본다. 포스터 '라이드', 프레임 왼쪽 위 재생·정지 버튼, 푸터의 버디 자리, 첫 화면 아래 요소에만 거는 스크롤 등장을 넣었다 |
| 13. 낮은 화면 | 후킹 크기, 세로 간격, 영상 폭이 화면 높이를 따라 줄어든다. 브라우저 창 안쪽 크기 1366×768, 1280×720, 1024×768, 375×667, 360×740에서 영상이 첫 화면에 35% 넘게 보여 로드 때부터 재생된다. 실링은 68px보다 작아지지 않고, 실링이 'Soon' 줄 아래로 내려오는 만큼 H1을 띄운다. 주소창을 뺀 실제 창이 더 낮은 기기(iPhone SE 2·3의 Safari 등)는 `docs/OPEN_ITEMS.md` 진행 메모를 본다 |
