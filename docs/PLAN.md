# 스딩 랜딩페이지 기획서 v2.0

Oct 28, 2026 · @tae hyeung kwon

**v1.1 변경(2026-10-28)**: 첫 화면을 'Coming Soon' 후킹(B안, 청첩장 느낌)으로 열고 영상은 바로 아래 섹션으로 옮겼다. 새 토큰, SEO 추가 항목 5개(소유확인 메타, IndexNow, 코드로 만드는 공유 이미지, DefinedTermSet, 오픈일 표기 통일), Next.js 16 기준 개발 사양을 반영했다. 시안은 `docs/design/`에 있다. 첫 화면 후킹과 영상 섹션은 v2.0에서 뺐다.

**v1.2 변경(2026-10-29)**: 지원 하한을 iOS·Safari 16.4로 올리고, 폰트를 저자가 배포한 다이내믹 서브셋으로 바꿨다. 2단계(히어로와 영상 시스템)를 만들며 낮은 화면의 후킹·영상 크기, 동작 줄이기 규칙, 영상의 `autoplay` 속성을 정리했다. 교차 검토 뒤 D-day 실링의 최소 폭과 그림자(`--seal-min`, `--shadow-seal`), 기획서에 없던 영상·버디 경우(밖에서 멈춘 영상, 화면 폭이 바뀔 때의 컷, 소리 파일이 없을 때와 멈춘 소리 영상의 버디)를 더했다. 브라우저 글자 크기를 키워도 후킹이 한 줄이도록 `--fs-display`에 상한을 더했다. 후킹, D-day 실링, 사운드 버디의 경우는 v2.0에서 뺐다.

**v1.3 변경(2026-10-31)**: 3단계(소개와 존 4개)를 만들며 기획서끼리 어긋나던 곳을 정리했다. 768~899px의 존은 설명 두 줄을 지키려고 텍스트와 미디어를 6열씩 쓴다. 고지 문구는 ZONE 03 표대로 미디어 바로 아래에 두고 ZONE 04도 같게 한다. 진행 점은 존 구간에 있을 때만 보인다. JS가 꺼져 있으면 재생 버튼을 숨긴다. 존 배치와 진행 점은 v2.0에서 뺐다.

**v1.4 변경(2026-10-31)**: 4단계(FAQ와 검색 대응)를 만들며 기획서에 없던 값을 정했다. FAQ 제목은 '자주 묻는 질문'이고 질문 글자는 서체 표에 더했다. 공유 이미지는 후킹이 'Coming Soon'일 때 히어로의 눈을 함께 그리고, `next/og`가 woff2와 가변 폰트를 읽지 못해 고정 굵기 폰트를 `assets/fonts/`에 둔다. IndexNow 키는 미리 만들어 두었다. 해시 주소로 바로 들어오면 로드가 끝날 때까지 부드러운 스크롤을 끄고, JS가 꺼져 있으면 부드러운 스크롤을 쓰지 않는다. 스테이징과 프리뷰의 `noindex`는 메타 태그 코드에도 적었다. canonical과 `og:url`은 `'./'`로 써서 페이지마다 제 주소를 가리키고, `og:title`과 `og:description`은 페이지의 `title`, `description`을 따른다. Lighthouse SEO는 미리보기가 `noindex`라 `sding.kr`에서 잰다. IndexNow 전송을 첫 공개와 정식 오픈 일정에 넣었고, 만드는 단계가 없던 `not-found.tsx`는 6단계에 넣었다. FAQ의 스토어 답은 주소가 있는 곳만 말한다. 공유 이미지의 눈은 v2.0에서 뺐다.

**v1.5 변경(2026-11-01)**: '가상 피팅'은 드레스 AI 합성을 풀어 쓴 말로 보고, 정의 문장 안에서 쓰도록 규칙을 고쳤다. 기획서에 없던 AI 웨딩홀 시뮬레이션의 정의 문장은 ZONE 04 설명의 말로 정했다. 두 문구는 임시이며 사용자가 나중에 직접 고친다(`docs/OPEN_ITEMS.md` '나중에 직접 고칠 문구'). 기능 이름은 v2.0에서 바꿨고, 두 임시 문구는 이름만 바뀌어 남았다.

**v1.6 변경(2026-11-01)**: 5단계(사전 신청)를 만들기 전에 공식 문서와 소스로 사양을 확인하고, 기획서의 코드대로면 실패하는 곳을 고쳤다. 번호 처리는 `+82` 자동 완성에서 끝자리가 잘려 저장되던 문제와 형식(010 + 2~9로 시작하는 8자리)을 바로잡았다. Supabase는 표 권한을 직접 주고, 중복 번호는 `upsert`로 넘겨 번호가 Postgres 로그에 남지 않게 했으며, 키 이름을 `SUPABASE_SECRET_KEY`로 바꿨다. Turnstile은 서버 검증에 시간 제한과 hostname·action 확인을 넣고 장애를 봇 실패와 나누었으며, 위젯은 제출한 폼에서만 그때 만든다. 서울 리전은 `vercel.json`으로 고정했다. 동의 고지는 체크박스 옆에 접지 않고 보이게 했고, 허니팟 칸, JS 끔, 'App Store'·'Google Play' 표기, QR(`uqr`, 하나만)을 정했다. 구현 뒤 교차 검토에서 전송 중 입력 잠금, 전송 시간 제한, 하이드레이션 전 입력 보존, 두 번 누른 CTA, iOS의 뒤 페이지 잠금, 로그의 HTTP 상태를 더했고, 코드 블록을 실제 파일에 다시 맞췄다.

**v1.7 변경(2026-11-01)**: 6단계(법적 페이지)를 만들기 전에 현행 법령과 업체 공식 문서를 조사해 초안의 사실을 맞췄다. 문서 이름은 표준지침 제20조의 '개인정보 처리방침'으로 고치고 푸터에서 다른 고지와 구분한다. 구제 기관에서 2026년 10월 2일 폐지된 대검찰청을 뺐다. Turnstile 스크립트는 폼에 입력을 시작해야 받도록 바꿔, 신청하지 않고 지나가는 방문자의 IP가 봇 확인 때문에 Cloudflare로 가지 않게 했다. 동의 고지의 목적에 '1회'를 더했다. 시행일과 처리 근거가 비어 있으면 운영 빌드가 멈춘다(`assertLegal()`). 약관은 의무를 지우는 조항 없이 안내로 쓴다. `src/content/legal.ts`, `LegalPage`, `src/styles/legal.css`를 더했고, 404 문구는 파크 지도 콘셉트로 정했다. 404의 파크 문구는 v2.0에서 바꿨다.

**v1.8 변경(2026-11-02)**: 7단계(분석과 점검)를 만들며 이벤트를 고쳤다. `form_submit`과 `video_progress`는 GA의 예약 이름이라 `waitlist_submit`, `video_milestone`으로 바꿨다. `video_milestone`에 3초 지점을 더해 시청률 지표를 낼 수 있게 했다. `waitlist_submit`은 요청 전에 막힌 잘못된 번호와 빠진 동의도 보낸다. `zone_view`는 세로로 긴 존을 위해 화면 높이의 50%도 기준으로 삼는다. Google 신호와 광고 개인화는 코드에서 끄고, 쿠키는 `sding.kr`에만 둔다. GA는 `@next/third-parties` 대신 인라인 초기화와 `next/script`로 붙였다. `AnalyticsEvents`를 더했다. `zone_view`는 v2.0에서 `feature_view`로 바꿨다.

**v1.9 변경(2026-11-04)**: 처리방침, 이용약관, 동의 문구를 Claude가 법령과 공식 지침에 대조해 검토하고, 다른 검토자의 반박 검토를 거친 수정을 반영했다. 변호사의 법률 의견은 아니다(검토서는 `docs/private/legal-review.md`). 동의 고지는 이용 목적 줄도 굵게 보이고, `CONSENT_VERSION`을 `2026-11-v2`로 올렸다. FAQ의 번호 답은 동의 고지의 보유 기간 값을 읽는다. 처리방침은 업체마다 국외 이전 사항과 거부 방법을 채우고, 아동, 보유 기간, 권리, 쿠키, 구제, 변경 절을 법령의 항목에 맞췄다. 국외 이전 근거(제28조의8제1항제3호가목), 처리 근거, 이전 유형을 넣었고 시행일만 남겼다. 출시 문자는 비광고 1회 안내로 보낸다. 법률사무소 소식지, 언론, 업체 블로그 출처는 공식 자료로 바꿨다. 보유 기간의 상한 날짜, 푸터 AI 문구, 검토가 낸 기획 변경은 사용자 결정을 기다린다(`docs/OPEN_ITEMS.md`).

**v1.10 변경(2026-11-04)**: 사용자가 검토의 권장안을 승인해 반영했다. 보유 기간은 '안내 문자를 보낸 뒤 5일 안에, 오픈이 늦어져도 2027년 6월 30일까지 파기'이고 `CONSENT_VERSION`은 `2026-11-v3`이다. 파일이 오기 전의 포스터 카드에는 'AI' 라벨을 붙이지 않고, 합성·시뮬레이션 존은 기능의 한계를 말하는 문장(`posterNotice`)을 둔다. 신청 폼의 동의 줄 아래에 '개인정보 처리방침 보기'와 '이용약관 보기'를 둔다. 오픈 전에는 히어로 날짜 줄, 마지막 CTA 제목, llms.txt, 푸터 AI 문구에 '예정'을 쓴다. 첫 공개는 GA4 없이 하고, 그동안의 지표는 Supabase 신청 건수와 검색 도구로 본다. 정찰제 표현, 같은 폼의 신청 취소, 1자 방문 합계는 아직 정하지 않았다.

**v1.11 변경(2026-11-05)**: 대표 연락처(전화, 이메일)와 개인정보 보호책임자(대표 정원창)를 받아 넣었다. 처리방침의 책임자 절에는 성명, 직위, 연락처를 적는다. 신청 폼 아래 '신청 취소하기'로 같은 자리에서 신청을 취소하게 했다(검토 P4). 서버는 같은 주소에서 `action: 'withdraw'`를 나눠 받고, Supabase 함수 `waitlist_withdraw`가 행을 지우고 날짜별 건수만 번호 없이 남긴다. 처리방침에 신청 취소와 문의·요구를 받을 때 처리하는 정보를 더했다. 문의 정보의 보유 기간은 회사가 정하고, 비어 있으면 운영 빌드가 멈춘다. `CONSENT_VERSION`은 `2026-11-v4`다.

**v1.12 변경(2026-11-05)**: 업체 공식 문서와 대조해 사실 세 가지를 고쳤다. 네이버 서치어드바이저에는 대표 도메인을 고르는 메뉴가 없어 www의 301 이동과 canonical로 맡긴다. IndexNow는 검색엔진에 키를 등록하는 절차가 없고 키 파일만 둔다. Turnstile 시험 비밀 키는 더미 토큰만 받고 실제 토큰은 거절한다. 업체 대시보드 설정 순서는 저장소 밖 `docs/private/setup-guide.md`에 있다.

**v1.13 변경(2026-11-05)**: 문의 메일(namu@sding.kr)을 대한민국에서 저장·처리하는 메일 서비스로 받기로 했다(OPEN_ITEMS 결정 질문 18). Google Workspace로 받으면 제휴 문의의 국외 이전 근거가 약하다는 검토의 권고를 따랐다. 주소는 그대로이고 받는 서버만 바뀐다. 업체가 정해지면 처리방침의 국내 위탁 묶음에 적고 `MAIL_VENDOR`를 채운다. v1.14에서 되돌렸다.

**v1.14 변경(2026-11-05)**: 같은 날 결정 질문 18을 다시 정했다. 이미 Google Workspace로 sding.kr 메일을 쓰고 있어, 문의 메일은 그대로 Google Workspace로 받고 처리방침에 국외 이전으로 공개한다. v1.13의 국내 메일 서비스 결정은 되돌렸다. 처리방침에 Google Workspace 묶음(이전 사항 다섯 가지), 근거 문장, 거부 방법을 넣고 `CONSENT_VERSION`을 `2026-11-v5`로 올렸다. 관리 콘솔 확인은 OPEN_ITEMS `workspace-console`이다. 운영 빌드의 `assertLegal()`은 문안에 한글로 시작하는 중괄호 빈칸이 남아도 멈춘다.

**v2.0 변경(2026-11-12)**: 대표가 고른 시안 2(시네마)로 페이지를 다시 짰다. '스딩 파크' 콘셉트(존 이름, ZONE 번호, 진행 점), 'Coming Soon' 후킹과 D-day 실링, 소개 섹션, 사운드 버디를 뺐다. 기능은 웨딩 가격 정찰제, AI 웨딩 플래너, AI 드레스 합성, 웨딩홀 시뮬레이션 네 개이고 이 이름으로 고정한다(결정 질문 1을 닫았다). 웨딩 체크리스트는 AI 웨딩 플래너 설명의 한 줄로 말한다. 첫 화면은 사진 위에 날짜 줄, 두 줄 제목, 보조 문장, CTA를 두고, 대표가 만들 광고 영상이 오면 그 자리에서 무음으로 돌며 '소개 영상 보기'가 전체 영상을 창으로 연다. 기능마다 큰 사진이나 영상 장면을 두고, AI로 만든 사진 바로 아래에 'AI로 만든 예시 이미지예요.'를 단다. Fish Audio 무료 요금제로 만든 사진 세 장은 상업적으로 쓸 수 없어 git 밖의 `public/media/preview/`에만 두고 로컬 커밋도 하지 않는다. 서버 전용 모듈 `src/lib/media-files.ts`가 빌드할 때 파일이 있는지 보고 없으면 흰 바탕에 주황 워드마크인 포스터 카드를 그리므로, 유료 요금제로 만든 파일이 `public/media/`에 커밋될 때까지 git에서 만드는 빌드(Vercel)는 다섯 미디어 자리가 모두 포스터 카드다. 그동안 첫 화면은 데스크톱에서 문구 오른쪽에 워드마크를 두고 폰에서는 문구만 둔다(`first-public-media`). 드레스와 웨딩홀 사진은 유료 요금제로만 만들고, 드레스는 슬라이더 대신 원본과 합성 두 장을 나란히 둔다. 색은 흰 바탕과 무채색 위의 오렌지 #FF5719 한 색이고 모서리는 0·4·8px이며 장식 그림자를 쓰지 않는다. 제목 글꼴은 `--ff-display` 토큰 하나로 Pretendard를 쓴다. 머리글에 기능 바로가기 네 개를 두고 짧은 이름을 기본 원칙 2의 예외로 정했다. 분석 이벤트는 `sound_toggle`을 빼고 `zone_view`를 `feature_view`로 바꿔 7개다. 헤더와 히어로 CTA는 지금처럼 신청 창을 열고, 신청 폼, 동의 고지, 신청 취소, `/api/waitlist`의 동작과 문구는 그대로다. 사운드 버디를 빼면서 처리방침 쿠키 절의 소리 안내 문장을 지우고 `CONSENT_VERSION`을 `2026-11-v6`으로 올렸다(대표에게 먼저 알렸고, 반대하면 되돌린다). 새 문구는 초안으로 넣었고 승인 전까지 OPEN_ITEMS `hero-copy`에 남는다. 시안은 `docs/design/cinema/`에 있다.

## 요약

스딩 랜딩페이지(sding.kr)는 기능 네 가지를 영화 스틸 같은 큰 사진 장면으로 보여 주는 원페이지(시네마)이며, 이 기획서는 Claude Code가 바로 만들 수 있는 개발 사양까지 담았다. 첫 화면은 히어로 사진 위에 날짜 줄, 두 줄 제목, 보조 문장, CTA를 둔다. 라이선스가 있는 히어로 사진 파일이 들어오기 전까지 공개 빌드는 데스크톱에서 같은 문구 오른쪽에 흰 바탕의 주황 워드마크 포스터를 두고, 폰에서는 문구만 둔다. 대표가 만들 소개 영상은 나중에 히어로 자리에서 무음으로 돌고, '소개 영상 보기'가 전체 영상을 창으로 연다. 스딩은 웨딩 가격 정찰제와 AI 기능 세 가지(AI 웨딩 플래너, AI 드레스 합성, 웨딩홀 시뮬레이션)를 내세운 웨딩 플랫폼이다. 정식 오픈은 2026년 12월 25일이다.

오픈 전에는 출시 알림 신청을 받고, 오픈 후에는 같은 자리가 앱 시작 버튼으로 바뀐다. 로그인·결제·회원 영역은 없다. 목표는 세 가지다. 처음 온 방문자가 10초 안에 스딩을 이해하게 하고, 출시 알림 신청을 받고, 검색과 AI 답변에서 스딩이 하나의 서비스로 인식되게 한다.

## 프로젝트 개요

스딩 랜딩페이지(sding.kr)는 사진과 영상으로 설레게 하고, 글은 필요한 만큼만 말해 사전 신청과 제휴 문의로 이어지는 원페이지다.

**정의 문장(모든 채널 공통)**: 스딩은 웨딩 가격을 정찰제로 투명하게 만들고, AI로 플래닝·드레스·웨딩홀을 미리 경험하게 하는 웨딩 플랫폼이다. 이 문장은 메타 설명, 히어로 보조 문장(같은 뜻을 다른 말로), FAQ 첫 답, JSON-LD, llms.txt, 공유 이미지, 보도자료에 같은 뜻으로 쓴다.

### 목표

1. 이해: 처음 온 방문자가 10초 안에 스딩이 무엇인지 안다.
2. 전환: 사전 신청(출시 알림)을 남긴다. 정식 오픈일(2026-12-25) 이후에는 앱 시작으로 바뀐다.
3. 발견: 구글·네이버 검색과 AI 답변에서 스딩이 하나의 서비스로 인식된다.

### 설계 원칙

1. 첫 화면의 주인공은 히어로 사진이다. 라이선스가 있는 사진 파일이 오기 전에는 흰 바탕의 주황 워드마크 포스터가 그 자리를 맡는다. 소개 영상이 오면 사진 자리에서 무음으로 돌고 '소개 영상 보기'가 전체 영상을 창으로 연다. 첫 화면 아래로 다음 섹션을 걸쳐 보이게 하는 장치는 두지 않는다.
2. 한 화면에 한 메시지. 헤드라인은 20자 안팎, 설명은 두 문장 이내.
3. 아이덴티티는 셋만 쓴다: 오렌지 #FF5719 한 색, 흰 바탕과 무채색, 각진 형태(0·4·8px). 장식 그림자는 쓰지 않는다.
4. 무음 기준으로 설계한다. 자막은 영상에 굽지 않고 WebVTT 자막 트랙으로 따로 두어 기본으로 켜고, 소리는 켜면 더 좋은 보너스로 둔다.
5. 로그인·회원가입·결제가 없다. 입력은 휴대폰 번호 한 칸과 동의 체크뿐이다.
6. 검색엔진과 AI가 읽을 텍스트를 영상 밖에도 둔다: 정의 문장, 영상 대본, FAQ.

첫 공개는 GA4 없이 한다(2026-11-04 검토 Q16). GA 데이터가 Google LLC로 가는 국외 이전에 동의 없이 쓸 근거가 없다는 판단이다. 그동안 사전 신청 수는 Supabase의 날짜별 신청 건수로 세고(번호 없이 합계만 남긴다), 검색 유입은 서치콘솔과 네이버 서치어드바이저로 본다. 방문자가 분모인 지표(전환율, 시청률, 기능 도달률)는 잴 방법을 정할 때까지 내지 않는다. 방문 통계 동의 창을 만들어 동의한 방문자에게만 GA4를 싣는 안과, 쿠키 없이 날짜별 합계만 쌓는 1자 방문 합계 가운데 고른다(`docs/OPEN_ITEMS.md` 결정 질문 15).

전환율과 시청률의 목표치는 방문자 분모를 잴 수 있게 된 뒤 2주간 기준선을 측정해 정한다. 시청률은 소개 영상이 올라간 뒤부터 잰다.

## 레퍼런스 분석: 위디

[위디(Wedi)](https://wedi.co.kr/)는 대표가 고른 레퍼런스다(2026-11-11). 가져오는 것은 구조, 리듬, 크기뿐이고 문구, 이미지, 영상, 색은 가져오지 않는다. 텍스트량과 접근성은 반대로 간다. 위디는 일정·체크리스트·예산·하객을 관리하는 웨딩 준비 앱이고, 스딩은 가격 정찰제와 AI 체험이 중심이라 겹치는 지점은 플래너 정도다. 2026-11-11에 잰 위디의 크기는 H1 72px(행간 80px), H2 60px(행간 69px), 본문 18px(행간 1.8)이다.

| 기능 6개가 같은 틀로 반복된다: 작은 키커, 헤드라인, 한 줄 설명, 화면 이미지 | 기능 4개를 같은 리듬(라벨, 두 줄 제목, 설명, 큰 미디어)으로 쌓고 배치는 장면마다 다르게 해 스크롤만으로 이해되게 한다 |
| 가입으로 가는 CTA가 상단 배너, 히어로, 마지막에 반복된다 | CTA 문구를 하나로 고정하고 3곳에 반복한다 |
| 기능마다 실제 앱 화면처럼 보이는 UI 카드를 둔다 | 앱 화면은 실제 녹화가 올 때만 넣고, 그 전에는 사진 장면을 쓴다. 그린 앱 화면은 쓰지 않는다 |
| 메타 설명에 기능 키워드를 모아 둔다 | 키워드 나열 대신 정의 문장 한 줄로 쓴다 |

### 다르게 갈 것

| 위디에서 본 것 | 스딩의 선택 |
| --- | --- |
| 헤드라인 아래에 큰 영상 프레임을 둔다 | 같은 리듬을 쓰되, 히어로 문구만 포스터 사진의 밝은 벽 위에 놓고 그 밖에서는 제목이 미디어를 덮지 않는다 |
| 블록마다 카드 안에 항목과 수치가 많다 | 블록당 라벨, 두 줄 헤드라인, 두 문장 이내의 설명, 큰 미디어가 전부다 |
| 확대를 막는 viewport 설정(user-scalable=no)을 쓴다 | 확대를 허용한다. 접근성 점검에서 확대 차단은 감점 항목이다 |
| 헤드라인마다 이모지를 쓴다 | 이모지도 장식 아이콘도 쓰지 않는다 |
| 포지션이 준비 관리 앱이다 | 스딩은 정찰제와 AI 체험이다. 플래너는 관리가 아니라 대신 짜 주는 쪽으로 쓴다 |

분석 기준은 2026-10-28에 추출한 페이지 텍스트와 같은 날 받은 첫 화면 스크린샷이다. 스크린샷에서 헤드라인 후킹 아래에 큰 영상 프레임이 있는 구조를 확인했다. 위디의 문구·이모지·색은 가져오지 않는다.

## 컨셉: 시네마

기능 4개를 영화 스틸처럼 큰 사진 장면으로 보여 준다. 굵은 제목은 미디어 옆이나 위에 두고 미디어를 덮지 않는다. 히어로 문구만 포스터 사진의 밝은 벽 위에 놓인다. 바탕은 낮의 흰 스튜디오이고, 글자는 잉크색, 색은 오렌지 한 색과 차가운 무채색, 형태는 각지다. 대표가 2026-11-11에 시안 2(시네마)를 골랐고, 시안은 `docs/design/cinema/mockup.html`에 있다.

| 순서 | 기능 | 장면 |
| --- | --- | --- |
| 1 | 웨딩 가격 정찰제 | 드레스, 반지, 부케, 청첩장, 턱시도에 같은 모양의 빈 가격표가 걸린 흰 쇼룸 |
| 2 | AI 웨딩 플래너 | 휴대폰 하나로 준비 일정을 함께 보는 커플 |
| 3 | AI 드레스 합성 | 같은 사람의 원본 사진과 드레스를 합성한 사진 |
| 4 | 웨딩홀 시뮬레이션 | 입구에서 버진로드로 이어지는 웨딩홀. 영상이 오면 1인칭으로 걷는다 |

### 적용 규칙

- 기능 라벨은 고정 용어를 그대로 쓴 평범한 글자 한 줄이다. 존 라벨, 섹션 번호, 알약 라벨은 쓰지 않는다. 알약 모양은 한 화면에 하나까지다(버튼 포함).
- 진행 점, 원 안의 아이콘, 그라데이션 포스터, 외곽선만 있는 큰 숫자, 점선, 카드 안의 카드를 쓰지 않는다.
- 배치는 장면마다 다르게 하고 글과 미디어를 좌우로만 번갈아 놓지 않는다. 장면별 배치는 '기능 공통 규칙'에 있다.
- 어두운 장면은 하나만 의도해서 둔다. 웨딩홀 영상이 생기면 그 장면이다. 그 전에는 어두운 면이 없다.
- 실존 웨딩홀이나 드레스 브랜드로 보이는 장면은 사용 허락을 받기 전에는 쓰지 않는다(`zone3-rights`, `zone4-hall`).

## 브랜드 시스템

브랜드 시스템은 오렌지 한 색, 흰 바탕과 무채색, 각진 형태 세 가지로 끝낸다. 밝고 뷰티한 인상은 이 셋의 비율에서 만든다.

색 비율은 바탕 60%, 면 30%, 오렌지 10%를 기준으로 한다. 큰 오렌지 면은 한 화면에 한 곳만 둔다. 포스터 카드의 주황 워드마크는 선으로 그린 글자 마크라 오렌지 면으로 세지 않는다. 라이트 모드만 지원하며 `color-scheme: light`를 명시한다.

### 색상 토큰

기준은 WCAG 2 AA다. 일반 글자는 4.5:1, 큰 글자와 그래픽은 3:1이며, 수치는 공식으로 직접 계산했다.

| 토큰 | 값 | 용도 | 대비 |
| --- | --- | --- | --- |
| `--orange` | `#FF5719` | 워드마크, 주 버튼 면, 체크된 상자, 표시 크기 날짜 | 흰색 위 3.17:1(큰 글자와 그래픽만) |
| `--orange-press` | `#EC4A0F` | 주 버튼 hover 면 | 흰 글자 3.78:1 |
| `--orange-ink` | `#D63A00` | 흰 바탕 위 작은 주황 글자, 체크된 상자 테두리, 폰 헤더 CTA | 흰색 4.70:1, `--gray-100` 4.28:1 |
| `--orange-ink-band` | `#C23400` | `--gray-100` 위 작은 주황 글자(드레스 라벨), 오류 글자(`--danger`) | `--gray-100` 5.05:1, 흰색 5.55:1 |
| `--ink` | `#111113` | 제목, 강조 글자, 포커스 링 | 흰색 18.86:1, `--gray-100` 17.16:1, 오렌지 위 5.95:1 |
| `--gray-700` | `#3F3F46` | 본문, 리드, 고지, 작은 글자 | 흰색 10.44:1, `--gray-100` 9.50:1 |
| `--gray-500` | `#71717A` | 흰 바탕 위 캡션과 푸터 글자, 입력칸과 체크 상자 테두리 | 흰색 4.83:1, `--gray-100` 4.40:1 |
| `--gray-200` | `#E4E4E7` | 가는 선, 포스터 카드 테두리 | 1.27:1. 장식 전용. 정보 전달에 쓰지 않음 |

| `--white` | `#FFFFFF` | 페이지 바탕, 오렌지 위 큰 글자 | 기본 배경 |

오렌지와 회색의 사용 범위는 대비 수치에서 나온 규칙으로 정한다.

- 오렌지 면 위 흰 글자는 20px·700 이상일 때만 쓴다(3.17:1). 주 버튼은 20px·700으로 고정한다.
- 작은 주황 글자는 흰 바탕에서 `--orange-ink`(4.70:1), `--gray-100` 위에서 `--orange-ink-band`(5.05:1)를 쓴다. `--orange-ink`는 `--gray-100` 위에서 4.28:1이라 글자에 쓰지 않는다.
- `--orange`는 흰 바탕 위의 그래픽, 면, 표시 크기 글자(마지막 CTA 제목의 날짜)에만 쓴다. `--gray-100` 위의 체크된 상자는 `--orange`가 2.88:1이라 테두리를 `--orange-ink`로 둔다.
- `--gray-500` 글자는 흰 바탕에서만 쓴다. `--gray-100` 위에서는 4.40:1이라 `--gray-700`을 쓴다.
- `--gray-200`은 장식 선과 포스터 카드 테두리에만 쓰고, 조작 요소의 유일한 테두리로 쓰지 않는다. 입력칸과 체크 상자 테두리는 `--gray-500`(그래픽 3:1 이상)이다.
- 오류와 실패 상태 글자는 `--danger`(#C23400)다. 색만으로 오류를 알리지 않는다.
- 사진 상태의 히어로 문구는 사진 위에 흰 베일을 깔고 놓는다. 화면 크기마다 문구를 숨긴 화면에서 글자 밑 배경을 재어 날짜 줄, 보조 문장, 캡션은 4.5:1, H1은 3:1 이상인지 확인하고, 모자라면 베일을 올린다. 포스터 상태에서는 문구가 흰 바탕 위에 있다.

### 서체

서체는 Pretendard Variable 하나만 쓴다. 한글과 영문이 같은 굵기 체계로 설계돼 있어 '스딩'과 'Sding'을 나란히 써도 어긋나지 않는다.

제목 글꼴은 토큰 `--ff-display` 하나로 정하고, 지금은 본문 글꼴 `--ff-body`와 같은 Pretendard Variable이다. 한글 800에서 시안의 Wanted Sans보다 0\~1.1% 좁을 뿐이라 시안에서 맞춘 줄바꿈이 그대로 맞는다. Wanted Sans로 바꾸려면 `--ff-display` 한 줄과 함께 자체 호스팅할 woff2 파일과 `OFL.txt`(내려받기라 대표의 허락이 필요하다), 그 `@font-face`와 preload 서브셋(`fonts.css`, `FONT_SUBSET`), 공유 이미지용 고정 굵기 woff(`assets/fonts/`)를 더한다(`display-font`). 굵기는 500(본문), 700(라벨, 버튼, FAQ 질문), 800(H1\~H3) 세 가지다.

폭 기준점은 900px 하나다. 900px 이상은 데스크톱 값, 899px 이하는 폰 값을 쓰고, H1, 신청 제목, H2만 `clamp()`나 `min()`으로 화면 폭을 따른다. 글자 크기는 화면 높이를 따르지 않는다. 정확한 값은 개발 사양의 토큰 블록에 둔다. H1은 어느 폭에서나 '가격이 보이는' / '결혼 준비' 두 줄이고, 900\~1021px에서는 첫 줄이 사진 속 신부의 머리카락에 닿지 않도록 92px보다 작다. 문단에는 `text-wrap: pretty`를 쓴다.

- 한글 줄바꿈은 `word-break: keep-all`을 쓰고, 제목에는 `text-wrap: balance`를 더한다.
- 본문 폭을 제한한다. 기능 설명은 34em(`--measure`), FAQ 답은 42em(`--measure-answer`), 법적 페이지 본문은 36em까지다.
- 가격 숫자에는 `font-variant-numeric: tabular-nums`를 쓴다.

브랜드명 표기는 한글 '스딩', 영문 'Sding'이다. 영문 대소문자는 \[확인 필요\].

### 로고

로고는 앱 아이콘에서 딴 주황 워드마크('Sding')다. 원본 벡터는 아직 없어 앱 아이콘에서 따라 그린 윤곽을 임시로 쓰고 `TODO(logo)`를 남긴다. 따라 그린 원본 SVG는 저장소 밖 `docs/private/brand/wordmark/`에 있다.

| 항목 | 내용 |
| --- | --- |
| 지금 쓰는 것 | 따라 그린 워드마크 윤곽(viewBox 1519.2×641, 가로세로 약 2.37:1). `Wordmark.tsx`가 인라인 SVG 심볼 하나로 두고 헤더, 푸터, 포스터 카드가 `<use>`로 쓴다. 색은 `currentColor`이고 `--orange`로 칠한다 |
| 바꾸는 법 | 원본 벡터가 오면 `Wordmark.tsx`의 윤곽(`d`)만 바꾸고, `--orange`가 원본 색과 같은지 확인한다(`brand-orange`) |
| 필요한 파일 | 오렌지 `logo.svg`, 흰색 `logo-white.svg`, 마크만 따로 있다면 `logo-mark.svg`, 앱 아이콘 원본 1024px |
| 크기 | 헤더 높이 32px(데스크톱), 24px(폰). 푸터 26px. 링크의 터치 영역은 44×44px 이상이다 |
| 여백 | 로고 높이의 0.5배 이상 |
| 금지 | 비율 변경, 그림자, 그라데이션, 지정 외 색 |
| 링크와 이름 | 헤더와 푸터의 로고는 `/#top`으로 가는 링크이고 이름은 '스딩 Sding 홈'이다(초안, `hero-copy`). 워드마크에 보이는 'Sding'을 이름에 넣어 WCAG 2.5.3을 지킨다. 로고 자리에 브랜드명을 글자로 다시 치지 않는다 |

파비콘과 앱 아이콘 같은 파생 파일 목록은 개발 사양에서 다룬다. 로고는 미디어가 아니므로 `MediaSlot`을 거치지 않는다.

### 모션

모션은 짧고 부드럽게 쓰며 영상과 경쟁하지 않는다. 기본 이징은 `cubic-bezier(.22, 1, .36, 1)`이다.

| 요소 | 동작 | 시간 |
| --- | --- | --- |
| 섹션과 히어로 | 스크롤할 때 떠오르는 효과와 등장 애니메이션을 쓰지 않는다. 글과 사진은 처음부터 보인다 | — |
| 버튼·링크 hover | 색이 바뀐다. 헤더 메뉴, FAQ 질문, 푸터 링크에는 밑줄이 생긴다. hover할 수 있는 기기에서만 건다 | 200ms |
| 버튼 press | 1px 아래로 눌린다 | 200ms |
| FAQ 열기 | 더하기 아이콘이 45° 돌아 ×가 된다. 답은 페이드 없이 바로 보인다 | 300ms |
| 신청 창, 완료 문구, 영상 덮개 | 투명도만 바뀐다 | 200ms, 400ms, 400ms |
| 큰 재생 버튼 hover | 1.04배로 커진다 | — |

`prefers-reduced-motion: reduce`에서는 이동과 확대를 모두 끈다. 토큰 블록의 전역 규칙이 애니메이션과 전환을 바로 끝내고 반복을 한 번으로 줄이므로, 투명도도 전환 없이 바로 바뀐다. 5초를 넘게 자동으로 움직이면 WCAG 2.2.2(멈춤·정지·숨김)를 채워야 하므로, 페이지에서 저절로 계속 움직이는 것은 늘 보이는 재생·일시정지 버튼이 있는 영상뿐이다.

### 아이콘과 이미지

- 아이콘은 조작용 글리프(재생, 일시정지, 닫기, 더하기)만 쓴다. 24px 격자, 선 두께 2px, 끝과 모서리 둥글게, `currentColor`로 그린 인라인 SVG다. 존 아이콘, 반짝임, 아이콘 CDN, 이모지는 쓰지 않는다. 동의 체크 표시는 CSS 마스크로 그린다. 푸터의 SNS 아이콘은 채널이 정해지면 더한다.
- 사진과 영상은 낮의 흰 스튜디오, 따뜻한 자연광, 약한 피부 보정을 기준으로 한다. 과한 필터는 피하고, 어두운 장면은 웨딩홀 영상 하나만 의도해서 둔다.
- 드레스 합성 이미지에는 화면에 보이는 'AI 합성' 표시를 붙인다. 랜딩에서는 이미지 위 라벨 대신 합성 사진 바로 아래 캡션 'AI 합성'으로 보인다. AI로 만든 예시 사진 바로 아래에는 'AI로 만든 예시 이미지예요.'(드레스와 웨딩홀은 기능 고지)를 단다. 표기 규칙은 회사정보·법적 표기 절에서 정한다.

## 페이지 구조

페이지는 헤더, 히어로, 기능 4개(웨딩 가격 정찰제, AI 웨딩 플래너, AI 드레스 합성, 웨딩홀 시뮬레이션), FAQ, 마지막 CTA, 푸터의 9개 블록을 한 줄로 쌓은 원페이지이고, 앵커 7개로 이동한다. 섹션마다 메시지는 하나뿐이다. 전역 요소는 신청 창이고, 소개 영상이 오면 소개 영상 창이 더해진다.

| 순서 | 블록 | 앵커 | 바탕 | 내용 |
| --- | --- | --- | --- | --- |
| 1 | 헤더 | — | 흰색 86%와 블러 | 워드마크, 기능 바로가기 4개(900px 이상), CTA |
| 2 | 히어로 | `top` | 사진, 또는 흰 바탕과 워드마크 포스터 | 날짜 줄, H1, 보조 문장, CTA, AI 캡션(사진 상태) |
| 3 | 웨딩 가격 정찰제 | `price` | 흰색 | 라벨, H2, 설명, 화면 폭 가득 16:9 미디어 |
| 4 | AI 웨딩 플래너 | `planner` | 흰색 | 왼쪽 글, 화면 오른쪽 끝까지 닿는 9:10 사진 |
| 5 | AI 드레스 합성 | `dress` | `--gray-100` 띠 | 원본과 AI 합성 3:4 두 장(파일 전에는 포스터 카드 한 장), 고지 |
| 6 | 웨딩홀 시뮬레이션 | `hall` | 흰색 | 화면 폭 가득 16:9 미디어, 고지 |
| 7 | FAQ | `faq` | 흰색 | 자주 묻는 질문, 첫 항목 펼침 |
| 8 | 마지막 CTA | `waitlist` | 흰색과 `--gray-100` 블록 | 제목과 설명, 신청 폼 |
| 9 | 푸터 | — | 흰색 | 회사 정보, 링크 3개, AI 안내, 저작권 |
| 전역 | 신청 창 | — | 어둡게 덮은 화면 위 흰 카드 | 헤더와 히어로의 CTA가 연다 |
| 전역(영상이 오면) | 소개 영상 창 | — | 어둡게 덮은 화면 | 히어로의 '소개 영상 보기'가 여는 `dialog#film` |

헤더와 히어로의 CTA는 신청 창을 열고, 마지막 CTA는 같은 폼을 페이지 안에 직접 보여 준다. 900px 이상에서는 헤더의 기능 바로가기 4개가 `/#price`, `/#planner`, `/#dress`, `/#hall`로 이동한다. 진행 점과 햄버거 메뉴는 두지 않는다. 바로가기를 누르면 포커스가 그 섹션의 제목으로 따라가고, `/privacy`나 `/terms`에서 눌러도 홈이 그려진 뒤 같은 제목으로 간다. 주소로 바로 들어온 경우(QR의 `/#waitlist` 등)에는 포커스를 브라우저에 맡긴다.

- 앵커 7개는 각 섹션 요소의 `id`이며 영문 소문자와 하이픈만 쓴다: `top`(히어로), `price`(웨딩 가격 정찰제), `planner`(AI 웨딩 플래너), `dress`(AI 드레스 합성), `hall`(웨딩홀 시뮬레이션), `faq`(FAQ), `waitlist`(마지막 CTA). 시안의 `signup` 대신 QR과 JS 없는 CTA가 쓰는 `waitlist`를 지킨다.
- 로고는 `/#top`으로 이동하고, JS 없이 CTA를 눌렀을 때는 `/#waitlist`로 이동한다. 헤더가 모든 페이지에 있으므로 `/`를 붙이고, 홈에서는 같은 문서 안에서 스크롤만 한다.
- 고정 헤더에 제목이 가려지지 않도록 `scroll-padding-top`을 쓴다. 값은 디자인 토큰에 있다.
- 앵커로 이동한 뒤 키보드 포커스가 따라가도록 섹션 제목에 `tabindex='-1'`을 둔다.
- 해시 주소로 바로 들어오면 로드가 끝날 때까지 부드러운 스크롤을 끈다. 스크롤하는 동안 글꼴이 바뀌어 위쪽 높이가 줄면 목적지를 지나치기 때문이다. JS가 꺼져 있으면 부드러운 스크롤을 쓰지 않는다.

## 섹션별 상세 기획

이 절은 블록 9개에 들어갈 내용과 문구를 정한다. 순서와 앵커는 페이지 구조 절을 따른다.

### 카피 규칙

카피는 해요체 초안이다. 사업 규칙이 정해지기 전의 문구에는 \[확인 필요\]를 달았고, 확정되면 `src/content/`의 해당 파일만 고친다.

- 문장은 짧게 쓴다. 헤드라인은 20자 안팎, 설명은 두 문장 이내다.
- 최고·최초·유일·1위 같은 표현은 근거 자료 없이 쓰지 않는다(표시광고법).
- 구매·주문·결제처럼 거래를 뜻하는 말은 피한다. 통신판매업 신고 전이라 거래로 오해될 문구를 만들지 않는다.
- AI가 만든 결과물에는 'AI 합성' 또는 'AI 시뮬레이션'이라고 밝힌다. 랜딩에 보이는 AI 예시 사진은 아래 캡션 규칙을 따르고, 드레스 합성 사진에는 캡션 'AI 합성'을 둔다(AI 서비스 고지 표).
- AI로 만든 예시 사진에는 그 파일을 보일 때만 미디어 바로 아래 흰 바탕에 'AI로 만든 예시 이미지예요.'(초안, `hero-copy`)를 13\~14px `--gray-500`(#71717A)로 단다. 드레스와 웨딩홀은 이 문장으로 시작해 기능의 한계를 더한 고지를 쓴다. 예외는 데스크톱 히어로 하나로, 캡션이 히어로 안 왼쪽 아래 컨테이너 선에 `--gray-700`(#3F3F46)으로 놓인다. 사진 위에 놓이므로 4.5:1 이상인지 잰다. 포스터 카드에는 캡션을 달지 않는다.

| 소개 영상 보기 | 소개 영상 파일이 있을 때만 CTA 옆에 그린다. 누르면 소개 영상 창을 연다. 파일이 없으면 버튼도 없고 '준비 중'도 쓰지 않는다 |
| 사진 상태 | 히어로 사진 파일이 있을 때다. 지금은 이 PC의 검토용 사본으로 만든 빌드에만 있고, 라이선스가 있는 파일이 커밋되면 모든 빌드가 이 상태다. 데스크톱은 높이 `max(640px, 100svh)`의 화면 폭 가득 사진 위 왼쪽 아래에 문구를 둔다. 사진은 위를 기준으로 잘라(`object-position: 24% 0`) 넓은 창에서는 바닥부터 잘리고 머리는 잘리지 않는다. 왼쪽에는 흰 베일(왼쪽 끝 66%, 26% 지점 42%, 50%부터 없음)을 깔고, 대비가 모자라면 두 값을 .06씩 .84와 .60까지 올린다. 폰은 문구 다음에 4:5 사진을 둔다. 사진은 페이지에서 가장 먼저 받는 이미지라 `fetchpriority="high"`로 받고 지연 로드하지 않는다 |
| 포스터 상태 | 라이선스가 있는 히어로 파일이 오기 전, git에서 만드는 모든 빌드(Vercel 미리보기와 첫 공개 포함)다. 데스크톱(900px 이상)은 흰 포스터 카드가 히어로 오른쪽 절반을 테두리와 베일 없이 채우고, 가운데 주황 워드마크는 높이 64px(900\~1066px)에서 1440px의 86px를 거쳐 112px(약 1867px부터)까지 커진다. 문구는 흰 바탕 위에 있고 어느 폭에서나 워드마크와 140px 이상 떨어진다. 폰(899px 이하)은 미디어 자리를 숨기고, 히어로는 CTA 아래 36px에서 끝난다. 이 상태에는 `<img>`, `<figure>`, 캡션이 없다 |
| AI 캡션 | 사진 상태에만 'AI로 만든 예시 이미지예요.'(초안)를 단다. 데스크톱은 히어로 안 왼쪽 아래 컨테이너 선(아래에서 24px)에 `--gray-700`, 폰은 사진 바로 아래 `--gray-500`이다 |
| 첫 화면 기준 | 두 상태 모두 1440×900과 390×844에서 날짜 줄, H1, 보조 문장, CTA가 스크롤 없이 첫 화면에 들어온다. 1440×900에서 날짜 줄 위쪽은 약 347px, CTA는 약 740\~803px다 |
| 오픈 후 | CTA는 '앱 시작하기', 날짜 줄은 '2026.12.25 정식 오픈'으로 바뀐다. 제목과 보조 문장은 바꿀 때만 새로 정한다(`live-copy`) |
| 소개 영상이 오면 | 사진 자리에서 소개 영상이 무음으로 반복 재생된다(데스크톱은 문구 뒤, 폰은 4:5 틀). 사진이 그려진 뒤에 붙이고, 자동 재생 규칙을 따르며, 늘 보이는 재생·일시정지 버튼을 히어로 오른쪽 아래에 둔다. 영상 위 문구의 대비를 프레임마다 다시 잰다. 영상의 첫 장면 정지 이미지(라이선스가 있는 요금제로 만든 것)는 히어로 사진으로 쓸 수 있다 |

### 소개 영상 창(영상이 오면)

대표가 만드는 소개 영상(광고 영상)이 오면 더한다. 지금은 만들지 않는다. 영상 섹션과 소개 섹션은 v2.0에서 뺐고, 정의 문장은 히어로 보조 문장(같은 뜻)과 FAQ 첫 답이 맡는다.

| 항목 | 내용 |
| --- | --- |
| 목적 | 방문자가 원할 때 소개 영상 전체를 소리와 함께 볼 수 있게 한다 |
| 여는 곳 | 히어로의 '소개 영상 보기'. 영상 파일(`MEDIA.film`)이 있을 때만 그린다 |
| 창 | `dialog#film`을 `showModal()`로 연다. 닫기 버튼, Esc, 바깥 누르기로 닫고 신청 창의 보호 장치(0.4초 안의 누름 버림, 누른 곳과 뗀 곳이 모두 밖일 때만 닫기, iOS의 `touchmove` 막기)를 그대로 쓴다. `command`와 `closedby`는 지원 하한(Safari 16.4)에서 쓸 수 없어 쓰지 않는다 |
| 프레임 | 데스크톱 16:9(`min(92vw, 160svh)`), 폰 4:5 컷(`min(92vw, 72svh)`). 뒤는 88%로 어둡게 덮는다 |
| 영상 | `controls muted playsinline preload="none"`, 포스터는 히어로 사진. 열면 무음으로 재생을 시작하고, 소리는 방문자가 영상 컨트롤로 켠다 |
| 자막과 대본 | 한국어 자막 트랙을 기본으로 켠다. 대본이 있으면 영상 아래 '영상 내용 글로 보기'(`details`)에 둔다. 창을 내기 전에 자막과 대본 절의 WCAG 1.2.5 선택을 마친다 |
| 포커스 | 열면 닫기 버튼으로 가고, 닫으면 '소개 영상 보기'로 돌아온다. 열린 동안 페이지 안 영상은 멈춘다 |
| 측정 | 창 안의 재생은 `media_id: film`으로 보낸다. 히어로의 배경 루프는 재지 않는다 |
| 구조화 데이터 | `VideoObject`는 `MEDIA.film`이 있을 때만 낸다 |

### FAQ

FAQ는 `details` 요소로 만들고, 답변은 닫혀 있어도 HTML에 들어 있게 한다. 제목은 '자주 묻는 질문'이다. 질문은 8개이며 요금 항목은 정책이 정해질 때까지 숨긴다. 답변의 첫 문장이 곧 답이고 질문의 주제어를 되풀이한다. 같은 데이터에서 FAQPage JSON-LD를 만든다. 목록은 가는 선으로 나눈 한 줄 목록이고, 질문 오른쪽의 더하기 아이콘은 열면 45° 돌아 ×가 된다. 첫 질문은 처음부터 펼쳐 두어 정의 문장이 누르지 않아도 보인다. 정의 문장은 `p` 요소의 일반 텍스트이고 이미지나 영상 안의 글자로 대신하지 않는다. 답은 굵은 첫 문장 없이 같은 굵기로 쓴다.

### 전역 요소

- 신청 창은 헤더와 히어로 CTA가 여는 `dialog`다. 안의 폼은 마지막 CTA의 폼과 같은 컴포넌트다. 어느 페이지에서나 열리도록 레이아웃에 하나만 두고, 제목은 CTA 문구, 설명은 마지막 CTA의 설명과 같다. 오픈 후에는 같은 창이 스토어 선택 창이 된다. 닫기 버튼, Esc, 바깥 누르기로 닫히고 입력값은 남는다. 키보드가 떠 있을 때 바깥을 누르면 키보드만 내린다. 바깥 누르기는 누른 곳과 손을 뗀 곳이 모두 카드 밖일 때만 닫는다. 창을 연 뒤 0.4초 안의 누름은 버린다. CTA를 두 번 눌렀을 때 창이 바로 닫히거나 읽지 않은 동의가 체크되지 않게 하기 위해서다. 다시 열면 카드는 맨 위에서 시작한다. 데스크톱은 입력칸에서, 터치 기기는 제목에서 포커스가 시작한다. 터치 기기에서 입력칸을 바로 잡으면 키보드가 동의 고지와 버튼을 가린다. 카드는 키보드에 가려지지 않게 가운데에 두고 안에서 세로로 스크롤한다. iOS는 주소창이 접혔거나 키보드가 떠 있으면 `overflow: hidden`을 넘어 뒤 페이지를 움직이므로 창의 `touchmove`를 직접 막는다. 카드 스크롤, 두 손가락 확대, 확대한 화면의 이동은 막지 않는다.
- 소개 영상 창은 소개 영상이 오면 히어로의 '소개 영상 보기'가 여는 `dialog#film`이다. 동작은 '소개 영상 창' 표와 영상·미디어 시스템 절을 따른다.
- 사운드 버디와 진행 점은 v2.0에서 뺐다.

## 영상·미디어 시스템

페이지 안 영상(히어로 루프와 기능 영상)은 화면에 들어오면 무음으로 자동 재생된다. 소리가 있는 영상은 소개 영상 하나이고, 방문자가 소개 영상 창을 열어 영상 컨트롤로 켤 때만 소리가 난다. 모든 영상은 무음으로 시작하며 소리 없이도 이해되도록 만든다. v2.0을 만든 때에는 페이지에 영상 파일이 없다.

### 자동 재생 규칙

재생 여부는 아래 표의 순서로 결정한다. 영상이 화면에 35% 이상 보이면 먼저 동작 줄이기·데이터 절약 설정을 확인하고, 꺼져 있으면 무음으로 `play()`를 부른다. 어떤 경우에도 영상 자리에는 포스터가 먼저 보인다.

이 규칙은 페이지 안 영상(히어로 루프와 기능 영상)에 쓴다. 소개 영상 창의 영상은 방문자가 창을 열 때만 재생한다.

| 순서 | 판단 | 그렇다 | 아니다 |
| --- | --- | --- | --- |
| 1 | 영상이 화면에 35% 이상 보이는가 | 2로 간다 | 포스터만 보인다. 재생 중이면 15% 아래에서 멈춘다 |
| 2 | 동작 줄이기나 데이터 절약이 켜져 있는가 | 대체 화면(포스터와 큰 재생 버튼) | 무음으로 `play()`를 부른다. 거부되면(iOS 저전력 모드 포함) 대체 화면 |

자동 재생이 막히거나 줄이기 설정이 켜져 있으면 포스터와 재생 버튼이 남고, 방문자가 누르면 그때 재생한다.

| 항목 | 규칙 |
| --- | --- |
| 속성 | `muted loop playsinline`. `autoplay` 속성은 쓰지 않는다. 속성이 있으면 브라우저가 동작 줄이기·데이터 절약 확인 전에 재생하므로, 재생은 아래 규칙대로 JS가 `play()`로 시작한다. 모든 영상은 `preload="none"`으로 시작한다 |
| 시작과 정지 | 화면에 35% 이상 보이면 `play()`, 15% 미만이면 `pause()`. `IntersectionObserver`로 판단한다 |
| 히어로 로딩 | 히어로 사진은 페이지에서 가장 먼저 받는 이미지다(폰에서는 LCP). `fetchpriority="high"`로 받고 지연 로드하지 않는다. 히어로 루프 영상은 사진이 그려진 뒤에 붙인다 |
| 소스 선택 | 화면 폭 899px 이하이면 모바일 컷을 쓴다(레이아웃의 폭 기준점과 같다). 선택은 JS의 `matchMedia`로 하고, 브라우저마다 지원이 다른 `video`의 `source media`는 쓰지 않는다. 폰을 돌리거나 창 폭을 바꿔 899/900px를 넘나들면 컷을 바꾸고, 재생 중이었으면 같은 시점에서 잇는다. 새 컷의 첫 프레임이 나올 때까지 포스터를 보인다. 지금의 `VideoPlayer`와 `VideoProvider`는 767px를 쓰며, 페이지에 첫 영상(소개 영상이나 기능 영상)을 붙일 때 899px로 바꾼다 |
| 대체 화면 | 포스터와 큰 재생 버튼. 동작 줄이기 설정, 데이터 절약 모드, iOS 저전력 모드, `play()` 거부일 때 보여 준다 |
| 일시정지 | 모든 영상 프레임에 작은 재생·정지 버튼을 항상 보이게 둔다(WCAG 2.2.2). JS가 꺼져 있으면 영상을 재생할 수 없으므로 재생 버튼을 모두 숨긴다. 히어로 루프는 버튼을 히어로 오른쪽 아래에 둔다. 버튼의 이름과 동작은 `play()`를 부른 순간(불러오는 중 포함)부터 '일시정지'다. 방문자가 멈춘 영상은 자동으로 다시 재생하지 않는다. 미디어 키나 잠금 화면처럼 페이지 밖에서 멈춘 영상도 방문자가 멈춘 것으로 본다. 페이지 밖에서 다시 재생하면 멈춘 표시도 풀린다 |
| 탭 전환 | 탭이 숨겨지면 모두 멈춘다. 돌아오면 화면 안(재생을 이어 가는 기준인 15% 이상)에 있고 방문자가 멈추지 않은 영상만 이어서 재생한다. 동작 줄이기에서 방문자가 직접 재생한 영상도 잇는다 |
| 동시 재생 | 최대 2개 |
| 접근성 | 영상에 `aria-label`로 장면 설명을 붙이고 포스터에는 `alt`를 쓴다. 영상 속 글자는 본문에도 같은 텍스트로 둔다 |
| 서버 | MP4에 `+faststart`를 적용하고 HTTP Range 요청을 지원한다(iOS Safari 필수). 파일명에 버전을 넣고 `immutable`로 캐시한다 |

### 소리

사운드 버디는 2026-11-12에 뺐다. 대표에게 기획서와 달라지는 점으로 먼저 알렸고, 반대하면 되돌린다(`buddy-drop`). 소리는 소개 영상에만 있고, 방문자가 소개 영상 창의 영상 컨트롤로 켤 때만 난다. 페이지 안 영상은 모두 무음이다. `VideoProvider`와 `VideoPlayer`에 남은 소리 코드는 쓰이지 않으며, 소개 영상을 붙일 때 그 파일로 시험하며 지운다.

| 항목 | 규칙 |
| --- | --- |
| 상태 저장 | 저장하지 않는다. 방문마다 무음으로 시작한다 |
| 재생 거부 | 소리를 켠 채 `play()`가 거부되면 `muted`로 다시 재생한다 |

### 자막과 대본

- 자막은 영상에 굽지 않고, 영상 위에 큰 글자를 넣지 않는다. 히어로 문구가 영상 위에 놓이기 때문이다. 대표가 주는 .srt를 WebVTT로 바꿔 소개 영상 창에 `<track kind="captions" srclang="ko" default>`로 둔다. 영상이 무음으로 시작하므로 자막은 기본으로 켠다. 같은 파일을 유튜브 업로드에도 쓴다.
- 대본은 있을 때만 소개 영상 창의 영상 아래 '영상 내용 글로 보기'(`details`)에 넣는다. 접근성과 검색·AI 인용에 모두 쓰인다.
- WCAG 1.2.5(AA, 음성 해설): 소개 영상 창을 내기 전에 둘 중 하나를 고른다. (가) 영상에 페이지에 없는 정보가 없고, 히어로 문구의 미디어 대체물이라고 밝힌다. (나) 음성 해설판을 만든다. 대본은 1.2.3과 1.2.8을 돕지만 그것만으로 1.2.5를 채우지 못한다(`transcript-place`).
- 히어로의 무음 루프는 `aria-hidden`이고 페이지에 없는 정보를 담지 않는다.

### 영상 제작 가이드

영상팀에 전달할 조건이다. 소리와 자막 조건은 페이지 설계와 맞물려 있어 먼저 합의한다.

- 두 벌을 만든다: 데스크톱 16:9(1920×1080), 모바일 4:5(1080×1350). 길이는 15\~30초이고, 처음 3초 안에 핵심 장면이 나오게 한다.
- 사이트는 소리를 끈 채 시작하므로 소리 없이도 이해되게 만든다.
- 자막은 영상에 굽지 않고 .srt 파일로 따로 준다. 영상 위에 큰 글자를 넣지 않는다(히어로 문구가 영상 위에 놓인다).
- MP4(H.264), 데스크톱 8MB, 모바일 5MB 안쪽. 첫 장면 정지 이미지(JPG) 1장을 함께 준다. 라이선스가 있는 요금제로 만든 이 이미지는 히어로 사진으로 쓸 수 있다.
- 히어로 문구가 영상 위에 놓이므로 모든 프레임에서 왼쪽 약 40%를 밝고 비어 있게 둔다.
- 힉스필드 유료 요금제로 만들고 워터마크가 없어야 한다. 상업적 이용 조건은 '권리와 라이선스' 표를 따른다.
- 모바일 4:5 컷은 따로 편집하는 것이 가장 좋다. 어렵다면 16:9 원본의 가운데 45% 폭 안에 핵심 피사체를 둔다.
- 초당 3회를 넘게 번쩍이는 장면은 넣지 않는다(WCAG 2.3.1).
- 음량은 -16 LUFS 안팎, true peak는 -1 dBTP 이하로 맞춘다. iOS는 `volume`을 바꿀 수 없어 파일의 음량이 곧 재생 음량이다.
- 첫 프레임을 포스터로 쓰므로 첫 1초에 핵심 장면이 보이게 한다.
- AI 인물이 체험담처럼 추천하는 대사는 쓰지 않는다. 가상 인물이 나오는 장면에는 그 인물이 나오는 동안 가까운 자리에 '가상인물'을 표기한다(공정위 추천·보증 심사지침 Ⅴ.5).
- AI로 제작한 영상이면 엔딩 카드에 'AI로 제작한 영상' 문구를 넣을 자리를 둔다. 유튜브 설명에도 같은 문구를 쓴다.
- 음원, 폰트, 소스 영상의 상업적 이용 허락 문서를 보관한다.

## SEO·GEO·AEO 설계

SEO·GEO·AEO는 따로 하지 않고 같은 기반 위에서 한꺼번에 처리한다. 기반은 한 문장 정의, 고정된 용어, HTML 안의 텍스트, 구조화 데이터 네 가지다. 페이지가 한 장이라 목표는 둘로 좁힌다. 브랜드명 검색에서 공식 사이트가 먼저 나오고, 정의형 질문에서 스딩이 답으로 인용되는 것이다.

### 기본 원칙

1. 정의 문장 하나를 메타 설명, 히어로 보조 문장, FAQ 첫 답, 구조화 데이터, llms.txt, 공유 이미지, 보도자료에 같은 뜻으로 쓴다.
2. 기능 이름 4개를 고정하고 모든 채널에서 똑같이 쓴다. 동의어는 정의 문장 안에서 풀어 쓸 때만 쓴다. 예외는 헤더의 기능 바로가기 하나다. 900px 폭에 전체 이름이 들어가지 않아 헤더에서만 짧은 이름 '정찰제', 'AI 플래너', '드레스', '웨딩홀'을 쓴다(초안, `nav-labels`).
3. 모든 카피는 서버가 만든 HTML에 넣는다(SSG). 영상이나 이미지 안에만 있는 정보는 두지 않는다.
4. FAQ 답변은 첫 문장이 곧 답이다. 질문의 주제어를 그 문장에 다시 써서, 문장만 떼어 가도 뜻이 통하게 한다.
5. 구조화 데이터의 값은 화면에 보이는 내용과 같아야 한다. 근거 없는 후기·평점·가격은 넣지 않는다.
6. 오픈일은 `launch.ts`의 도우미로만 만든다. 문장은 오픈 전 '2026년 12월 25일 정식 오픈 예정', 킥커는 '2026.12.25', CTA는 '12월 25일'로 쓰고 히어로, FAQ, JSON-LD, llms.txt가 같은 날짜를 말하게 한다.

### 고정 용어

| 고정 용어 | 쓰지 않는 변형 | 비고 |
| --- | --- | --- |
| 웨딩 가격 정찰제 | 가격 고정제, 정가제 | 정의는 적용 범위가 정해진 뒤 확정 \[확인 필요\] |

정의 문장과 용어별 한 줄 설명은 `src/content/`에 한 번만 쓴다. 메타 태그, 구조화 데이터, llms.txt가 같은 값을 읽는다.

기능별 한 줄 정의는 FAQ 표의 답변 첫 문장이다. 웨딩홀 시뮬레이션은 FAQ 질문이 달라서 정의를 따로 둔다: '웨딩홀 시뮬레이션은 입장부터 버진로드까지, 방문 전에 분위기와 동선을 먼저 걸어 보는 기능이에요.' 웨딩홀 시뮬레이션 설명의 말만 쓴 임시 문장이고, v2.0에서 이름만 바꿨다(`term-def`). 화면에는 없고 구조화 데이터와 llms.txt에만 나간다. 이름 네 개는 대표가 2026-11-11에 정한 표기다. AI 웨딩 플래너, AI 드레스 합성, 웨딩홀 시뮬레이션 줄의 '쓰지 않는 변형' 첫 이름은 v2.0에서 바꾼 옛 이름이다.

```ts
};

export const viewport: Viewport = {
  width: 'device-width', initialScale: 1, themeColor: '#FFFFFF',   // tokens.css --white와 같다
  // maximumScale, userScalable은 지정하지 않는다(확대 허용)
};
```

- 공유 이미지는 `src/app/opengraph-image.tsx`가 1200×630 PNG로 만든다. 흰 바탕에 주황 워드마크, 날짜 줄(`launchDotted()`와 '정식 오픈 예정', 오픈 뒤 '정식 오픈'), 두 줄 H1(`COPY.hero.h1`), 정의 문장(`SITE.definition`)을 글자로만 그린다. 사진, 눈, 후킹 문구는 없고 300KB 이하다. 워드마크는 `Wordmark.tsx`의 윤곽을 `--orange`로 칠한 데이터 URI SVG이고, 로고 원본이 오면 그 윤곽만 바꾼다. `next/og`는 woff2와 가변 폰트를 읽지 못해 Pretendard 고정 굵기 woff를 `assets/fonts/`에 두고 300과 800 두 굵기만 읽는다. 방문자에게는 내려가지 않는다. 문구를 바꾸면 글자가 이 폰트(한글 2,780자 서브셋)에 있는지 확인한다. 없으면 `next/og`가 렌더링 때 외부에서 글꼴을 받는다. alt는 `SITE.ogAlt`다. 페이지와 같은 `revalidate = 3600`으로 다시 만들어 오픈일에 오픈 후 문구로 바뀌게 한다. 다시 만들기는 요청이 와야 시작하고 그 요청은 이전 이미지를 받으므로, 오픈일 1시(KST)가 지나 `/opengraph-image`를 열어 새 문구를 확인한 뒤 카카오 공유 캐시를 지운다.
- 소유확인 메타 태그는 환경 변수 `NEXT_PUBLIC_GOOGLE_VERIFICATION`, `NEXT_PUBLIC_NAVER_VERIFICATION`에서 읽는다. 구글은 DNS TXT 인증을 기본으로 하고 메타 태그는 보조로 둔다. 네이버 서치어드바이저는 메타 태그로 인증한다.

`www.sding.kr`은 `sding.kr`로 301 이동한다. 네이버 서치어드바이저에는 대표 도메인을 고르는 메뉴가 없다. 네이버 가이드대로 www와 www 없는 주소를 301로 한쪽에 모으고 canonical을 `sding.kr`로 둔다. 카카오톡 미리보기는 OG 태그를 읽으므로, 이미지나 문구를 바꾸면 카카오 공유 디버거에서 캐시를 지운다.

### 크롤러와 색인 파일

AI 크롤러는 모두 허용하고 봇마다 규칙을 따로 쓴다. 스타트업에는 이 방식이 낫다는 권고를 따른 것이다. Anthropic 봇 3개는 각각 지시문이 있어야 하고, IP로 막지 않는 편이 좋다([Anagram, 2026-06-05](https://www.anagram.ai/blog/ai-crawlers-explained-gptbot-claudebot-perplexitybot-and-how-to-let-them-in-2026)).

| 토큰 | 운영사 | 유형 |
| --- | --- | --- |
| GPTBot | OpenAI | 학습 |
| OAI-SearchBot | OpenAI | 검색 |
| ChatGPT-User | OpenAI | 사용자 요청 |
| ClaudeBot | Anthropic | 학습 |
| Claude-SearchBot | Anthropic | 검색 |
| Claude-User | Anthropic | 사용자 요청 |
| PerplexityBot | Perplexity | 검색 |
| Perplexity-User | Perplexity | 사용자 요청 |
| Google-Extended | Google | 생성형 AI 활용 허용 신호 |
| Yeti | 네이버 | 검색 |

```ts
// src/app/robots.ts
const BOTS = ['Yeti', 'GPTBot', 'OAI-SearchBot', 'ChatGPT-User', 'ClaudeBot', 'Claude-SearchBot',
  'Claude-User', 'PerplexityBot', 'Perplexity-User', 'Google-Extended'];

export default function robots(): MetadataRoute.Robots {
  if (process.env.NEXT_PUBLIC_SITE_ENV !== 'production') {
    return { rules: { userAgent: '*', disallow: '/' } };   // 스테이징·프리뷰는 색인 금지
  }
  const rule = (userAgent: string) => ({ userAgent, allow: '/', disallow: '/api/' });
  return { rules: ['*', ...BOTS].map(rule), sitemap: 'https://sding.kr/sitemap.xml' };
}
```

학습용 봇만 막고 싶으면 GPTBot, ClaudeBot, Google-Extended 규칙의 `allow`를 `disallow: '/'`로 바꾼다. 검색과 사용자 요청 봇은 계속 허용한다. 사이트맵에는 `/`, `/privacy`, `/terms` 세 주소만 넣는다.

IndexNow 키 파일을 `public/{키}.txt`로 둔다. 키는 소유자가 정하는 공개 값이라 무작위로 만들어 두었다. 검색엔진에 키를 등록하는 절차는 없고, 참여 검색엔진끼리 받은 주소를 나눈다. 네이버도 IndexNow를 받는다. 다른 키를 쓰게 되면 파일과 아래 요청의 `key`를 함께 바꾼다. 배포 뒤에는 IndexNow로 바뀐 주소를 알린다. 첫 공개 날에는 세 주소를, 정식 오픈 날에는 홈 주소를 보낸다. 응답이 200이나 202면 접수된 것이다.

```bash
curl -i -X POST https://api.indexnow.org/indexnow -H "Content-Type: application/json; charset=utf-8" -d '{"host":"sding.kr","key":"9c7495293e61b2ab93f040374f6033e7","urlList":["https://sding.kr/","https://sding.kr/privacy","https://sding.kr/terms"]}'
```

### 구조화 데이터

JSON-LD는 `@graph` 하나에 노드 5개를 담고 `@id`로 서로 잇는다. 소개 영상(`MEDIA.film`)이 오면 `VideoObject`가, 오픈 후에는 `MobileApplication`이 더해진다. `DefinedTermSet`은 고정 용어 4개의 정의를 담아 정의형 질문에서 인용될 근거를 준다. 값은 content 파일에서 읽고, 빈 문자열과 빈 배열은 `prune()`으로 뺀다.

```ts
// src/lib/jsonld.ts
import { ctaMode } from './launch';
import { prune } from './prune';
import { COMPANY } from '@/content/company';
import { faqFor } from '@/content/faq';
import { FEATURES } from '@/content/features';
import { COPY, SITE } from '@/content/site';

const home = `${SITE.url}/`;
const org = `${SITE.url}/#org`;
const site = `${SITE.url}/#website`;
const terms = `${SITE.url}/#terms`;

// 소개 영상(MEDIA.film)이 오면 present()로 파일을 확인해 VideoObject 노드를 더한다(PLAN '구조화 데이터')

// ctaMode()는 스토어 주소가 있어야 'live'가 되므로 이 노드는 앱이 나온 뒤에만 나간다(PLAN 'CTA 전환')
function app() {
  const { ios, android } = SITE.store;
  return {
    '@type': 'MobileApplication', '@id': `${SITE.url}/#app`, name: COMPANY.brandName,
    operatingSystem: [ios && 'iOS', android && 'Android'].filter(Boolean).join(', '),
    installUrl: [ios, android], publisher: { '@id': org },
  };
}

// 노드를 @graph 하나에 담아 @id로 잇는다. 값은 화면과 같은 content 파일에서 읽는다
export const graph = () => {
  const mode = ctaMode();
  return prune({
    '@context': 'https://schema.org',
    '@graph': [
      { '@type': 'Organization', '@id': org, name: COMPANY.brandName, alternateName: COMPANY.brandNameEn, legalName: COMPANY.legalName,
        url: home, logo: `${SITE.url}/icons/icon-512.png`, description: SITE.description,
        foundingDate: COMPANY.openedAt, taxID: COMPANY.bizRegNo,
        address: { '@type': 'PostalAddress', streetAddress: COMPANY.street, addressLocality: COMPANY.locality,
          addressRegion: COMPANY.region, addressCountry: 'KR' },
        sameAs: SITE.sameAs },
      { '@type': 'WebSite', '@id': site, url: home, name: COMPANY.brandName, inLanguage: 'ko-KR', publisher: { '@id': org } },
      { '@type': 'WebPage', '@id': `${SITE.url}/#webpage`, url: home, name: SITE.title,
        isPartOf: { '@id': site }, about: { '@id': org }, inLanguage: 'ko-KR',
        primaryImageOfPage: { '@type': 'ImageObject', url: `${SITE.url}/opengraph-image` } },
      { '@type': 'DefinedTermSet', '@id': terms, name: COPY.terms, inLanguage: 'ko-KR',
        hasDefinedTerm: FEATURES.map((f) => ({ '@type': 'DefinedTerm', name: f.feature, description: f.definition,
          inDefinedTermSet: { '@id': terms } })) },
      mode === 'live' ? app() : null,
      { '@type': 'FAQPage', '@id': `${SITE.url}/#faq`,
        mainEntity: faqFor(mode).map((item) => ({ '@type': 'Question', name: item.q, acceptedAnswer: { '@type': 'Answer', text: item.a } })) },
    ],
  });
};
```

- 서버 컴포넌트에서 `application/ld+json` 스크립트로 출력한다. `JSON.stringify` 결과의 `<`는 유니코드 이스케이프로 바꿔 `</script>`로 오인되지 않게 한다.
- `VideoObject`는 소개 영상(`MEDIA.film`)이 들어오고 `uploadDate`와 `thumbnailUrl`이 채워진 뒤에만 출력한다. v2.0의 코드에는 아직 그 노드가 없다.
- `foundingDate`는 법인 설립등기일을 확인하기 전 임시값이다 \[확인 필요\].
- 정식 오픈 후 스토어 주소가 생기면 `MobileApplication` 노드를 더한다. 앱이 없는 지금은 넣지 않는다.
- 후기·평점·가격 노드는 근거가 생기기 전까지 넣지 않는다.
- FAQPage는 구글 리치 결과를 노리는 것이 아니라 기계가 읽기 쉽게 하려고 둔다.

### llms.txt

llms.txt는 넣되 효과를 기대하지 않는다. 주요 AI 업체 중 인용에 쓴다고 밝힌 곳이 없고, 구글도 쓰지 않는다고 했다. 채택률은 상위 100만 사이트의 5\~6% 수준이며 소개형 사이트에서의 가치는 낮다고 평가된다([Crocoblock, 2026-10-09 갱신](https://crocoblock.com/blog/llms-txt-for-wordpress-full-guide/)). 비용이 거의 들지 않으므로 `public/llms.txt`에 20줄 안팎만 둔다. 내용은 정의 문장, 기능 4개의 한 줄 설명, 회사 정보, 링크 3개이며 `src/content/`에서 생성한다. 생성은 빌드 직전(`prebuild`)에 스크립트가 한다. 서버 코드를 늘리지 않도록 라우트로 만들지 않는다.

### 네이버 대응

네이버에서는 이 페이지가 모든 검색어를 맡지 않는다. 네이버는 2025년 3월 27일 AI 브리핑을 시작했고, 정보성 검색어 맨 위에 출처 링크와 함께 보여 준다([네이버 보도자료](https://navercorp.com/media/pressReleasesDetail?seq=32374)). 광고성이 강한 추천·비교·가격·견적 검색어보다 원인·이유형 검색어에서 더 자주 뜨고, 쓰인 콘텐츠의 약 70%가 네이버 UGC라는 분석이 있다([1포인트, 2026-09-04](https://1point.kr/blog/insights/naver-seo-ai-briefing-3-steps/)). 그래서 검색어 유형별로 맡는 채널을 나눈다.

### AI 서비스 고지

AI 기본법은 2026년 1월 22일부터 시행 중이다. 제31조는 생성형 AI 서비스임을 미리 알리고, 결과물에 AI 생성 표시를 하고, 실제와 구분하기 어려운 결과물은 명확히 알리도록 정한다. 의무는 AI 제품·서비스를 이용자에게 최종적으로 제공하는 사업자에게 있고, 타사 도구로 만든 결과물을 게시만 하는 이용자에게는 없다([과기정통부 「인공지능 투명성 확보 가이드라인」 2쪽](https://www.msit.go.kr/bbs/documentView.do?atchFileNo=52249&fileOrdr=1), [지원데스크 사례집 23쪽 사례 01](https://www.sw.or.kr/common/board/Download.do?bcIdx=65415&cbIdx=390&streFileNm=7516b720-1c92-4fad-ade3-695d4136e77f.pdf)). 개정법은 7월 21일 시행됐다. 법과 시행령 부칙에는 계도기간이 없다. 지원데스크 FAQ가 최소 1년 이상 사실조사·과태료를 유예한다고 안내하지만 종료일은 없고 의무도 그대로이므로(사례집 37쪽 사례 20) 앱 출시 때부터 고지한다.

스딩은 플래너, 드레스 합성, 웨딩홀 시뮬레이션을 직접 제공하므로 사업자로 보고 설계한다. 드레스 합성은 실제와 구분하기 어려운 결과물일 가능성이 커서 가장 눈에 띄게 표시한다.

### 법적 페이지

`/privacy`와 `/terms`는 첫 공개 전에 푸터에 연결한다. 초안은 개발 단계에서 템플릿으로 만들고 변호사 검토 뒤에 공개한다.

- `/privacy`: 수집 항목·목적·보유 기간, 처리 위탁, 국외 이전, 정보주체의 권리와 행사 방법, 파기 절차, 안전성 확보 조치, 분석 도구(GA4)와 쿠키, 개인정보보호책임자, 시행일과 변경 이력.
- `/terms`: 서비스 소개와 현재 단계(출시 알림), 생성형 AI 사전 고지와 결과물 표시, 결과물의 한계, 지식재산권, 문의처, 시행일.
- 문구는 `src/content/legal.ts`에 두고 `LegalPage`가 그린다. 본문은 해요체다. 표 대신 라벨과 값의 목록을 써서 320px에서도 가로 스크롤이 없다.
- 제목은 '주식회사 스딩 개인정보 처리방침'이다. 표준지침 제20조는 명칭을 '개인정보 처리방침'으로 쓰고 글자 크기나 색으로 다른 고지와 구분하라고 정한다. 푸터는 굵기와 색으로 구분한다(700, `--ink`).
- 동의 고지의 항목, 목적, 보유 기간은 같은 값을 읽는다. GA 항목은 `NEXT_PUBLIC_GA_ID`가 있을 때, Cloudflare의 미디어 항목은 `NEXT_PUBLIC_MEDIA_BASE`의 도메인이 사이트와 다를 때만 나온다.
- 시행일(`LEGAL_DATE`), 국외 이전 근거(`TRANSFER_BASIS`), 신청 기록과 자동 처리 정보의 처리 근거(`RECORD_BASIS`, `AUTO_BASIS`), 업체별 이전 유형(`TRANSFER_TYPE`)은 검토를 마쳐야 넣는다. 하나라도 비어 있으면 운영 빌드가 멈춘다(`assertLegal()`). 문의 정보 보유 기간(`INQUIRY_RETENTION`)과 문의 메일 업체(`MAIL_VENDOR`)도 비어 있으면 멈추고, 처리방침과 약관 문안에 한글로 시작하는 중괄호 빈칸(업체명 자리 같은 것)이 남아도 멈춘다. 스테이징과 미리보기에서는 초안이 보인다. 2026-11-04 법령 검토로 시행일 밖의 값을 넣었다. 국외 이전은 제28조의8제1항제3호가목으로 두고, 업체마다 이전 사항 다섯 가지(항목, 나라·때·방법, 받는 곳과 연락처, 목적과 보유 기간, 거부 방법과 효과)를 빠짐없이 적어야 성립한다. 시행일은 첫 공개 전에 할 일(`docs/OPEN_ITEMS.md`의 `legal-review`)을 마친 뒤 실제 첫 공개일로 넣는다.
- 업체가 맡은 일과 업체가 스스로 쓰는 일을 나누어 적는다. 모든 업체를 수탁자로 단정하지 않는다. 맡긴 일에서는 수탁자로 적고, 업체가 스스로 정해 쓰는 일은 '직접 쓰는 목적'으로 따로 적는다(2026-11-04 검토).
- 구제 기관은 개인정보 분쟁조정위원회, 개인정보침해 신고센터, 경찰청 사이버범죄 신고시스템 세 곳이다. 대검찰청은 2026년 10월 2일 폐지됐다. 공개 직전에 번호와 주소를 다시 확인한다.
- `/terms`는 회원과 결제가 없는 사이트의 안내다. 방문자에게 의무를 지우는 조항, 포괄 면책, 서비스를 마음대로 바꾸거나 멈출 권한, 이용을 동의로 보는 문장, 관할 조항, 결제와 환불, '정찰제', 문자 수신 동의를 넣지 않는다. 앱을 출시할 때 앱 약관을 따로 쓴다.
- 없는 주소는 `not-found.tsx`가 '페이지를 찾을 수 없어요'와 홈 링크를 보인다. canonical과 공유 이미지는 넣지 않는다.
- `/terms`의 기능 이름은 `FEATURES`를 따른다. `legal.ts`가 기능을 읽는 코드는 `docs/private/legal-facts.md` 7절을 읽은 뒤 바꾼다. v2.0에서 사운드 버디를 빼며 처리방침 쿠키 절의 소리 안내 문장을 지웠고, `CONSENT_VERSION`은 `2026-11-v6`이다.

### 변호사 검토 요청 목록

1. 통신판매업·통신판매중개업 신고 필요 여부와 시점.

5. 영상 생성 도구 약관과 가상 인물 표기.
6. 국외 이전의 근거. 무료 출시 알림 신청이 제28조의8제1항제3호의 계약인지, 1호의 별도 동의가 필요한지. 답에 따라 신청 폼이 바뀔 수 있다.

## 개발 사양

개발은 Next.js(App Router)로 정적 생성한 원페이지이며, 모든 문구와 값은 `src/content/`에 두고 컴포넌트는 읽기만 한다. 서버 코드는 사전 신청 API 하나뿐이다.

### 디자인 토큰

브랜드 시스템 절의 값을 그대로 옮긴 파일이다. 폭 기준점은 900px 하나이고, 900px 이상이면서 860px보다 낮은 창에만 높이 규칙을 하나 둔다. 미디어 쿼리는 사용자 지정 속성을 읽지 못하므로 `899px`과 `900px`은 스타일 파일마다 숫자로 쓴다. 법적 페이지의 `legal.css`는 읽기용 기준점(640px, 1024px, `min-height: 720px`)을 따로 둔다. 토큰 이름은 Tailwind 테마 이름공간(`--color-*`, `--font-*`, `--text-*`, `--radius-*`, `--tracking-*`, `--leading-*`, `--ease-*`, `--container-*`)과 겹치지 않게 짓는다. `globals.css`의 `@theme inline`이 같은 이름을 선언하면 자기 자신을 가리켜 값이 사라진다. 원색은 `--이름: #RRGGBB;` 꼴로 한 줄에 하나씩 쓴다. 공유 이미지와 아이콘 스크립트가 정규식으로 읽는다.

```ts
import { COPY } from '@/content/site';

const PREVIEW_DIR = join(process.cwd(), 'public', 'media', 'preview');   // 앞부분을 고정해 파일 추적이 public 전체로 번지지 않게 한다

export function present(spec: MediaSpec): boolean {
  if (spec.kind === 'pair') return present(spec.before) && present(spec.after);
  if (spec.kind === 'video') return Boolean(spec.src);
  if (!spec.desktop.file) return false;
  if (!spec.preview) return true;
  const arts = spec.phone ? [spec.desktop, spec.phone] : [spec.desktop];
  return PREVIEW_ON && arts.every((a) => names(a).every((n) => existsSync(join(PREVIEW_DIR, n))));
}

export function noteFor(id: MediaId): string {
  const spec = MEDIA[id] as MediaSpec;
  const feature = FEATURES.find((f) => f.id === id);
  if (!present(spec)) return feature?.posterNotice ?? '';
  if (feature?.notice) return feature.notice;
  return isAi(spec) ? COPY.media.aiCaption : '';
}
```

### 환경 변수

환경 변수는 공개 6개, 비공개 3개이며, 비공개 값은 서버 코드에서만 읽는다. 실제 값은 저장소가 아니라 호스팅 설정에 넣는다.

| 이름 | 공개 여부 | 용도 | 비고 |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_SITE_ENV` | 공개 | `production` 또는 `preview` | `production`일 때만 색인을 허용하고 `assertCompany()`와 `assertLegal()`을 실행한다 |
| `NEXT_PUBLIC_MEDIA_BASE` | 공개 | 영상·이미지 주소의 앞부분 | 운영은 `https://sding.kr/media`처럼 절대 주소. 로컬은 비워 두면 `/media` |
| `NEXT_PUBLIC_GA_ID` | 공개 | GA4 측정 ID | 비어 있으면 GA 스크립트를 넣지 않고 아무것도 보내지 않는다. 빌드 때 읽으므로 바꾸면 다시 배포한다. 첫 공개에는 비운다. 넣으려면 방문 통계 동의 창을 먼저 만든다 |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | 공개 | Turnstile 위젯 키 | 비어 있으면 폼이 전송 단계에서 '잠시 후 다시 시도해 주세요.'를 보인다 |
| `NEXT_PUBLIC_GOOGLE_VERIFICATION` | 공개 | 구글 서치 콘솔 소유확인 메타 값 | 비어 있으면 태그를 넣지 않는다. 구글은 DNS TXT 인증이 기본이다 |
| `NEXT_PUBLIC_NAVER_VERIFICATION` | 공개 | 네이버 서치어드바이저 소유확인 메타 값 | 비어 있으면 태그를 넣지 않는다 |
| `TURNSTILE_SECRET_KEY` | 비공개 | 토큰 검증 | 서버 코드에서만 읽는다. 사이트 키와 한 쌍으로 같은 환경에 넣는다 |
| `SUPABASE_URL` | 비공개 | DB 주소 | 미리보기 배포에는 운영 값을 넣지 않는다 |
| `SUPABASE_SECRET_KEY` | 비공개 | 서버 전용 키(`sb_secret_`로 시작) | 브라우저 번들에 들어가면 안 된다. 구식 `service_role` 키는 2026년 말에 없어질 예정이라 쓰지 않는다 |

- 저장소에는 이름만 적은 `.env.example`을 두고, `.env*` 파일은 `.gitignore`에 넣는다.
- 미리보기 배포에는 운영 DB 키를 넣지 않는다. 키가 없으면 신청 API는 503을 돌려준다. 비공개 값은 Vercel의 Production 범위에 Secret으로만 넣는다. Supabase 프로젝트는 Vercel Marketplace가 아니라 Supabase에서 직접 만든다. Marketplace로 만들면 미리보기로 키가 퍼질 수 있고 주 처리자도 바뀐다.
- Turnstile 키는 환경마다 다르다. 개발과 미리보기는 Cloudflare가 공개한 시험 키 한 쌍을, 운영은 실제 키 한 쌍을 쓴다. 시험 키와 실제 키를 섞으면 모든 신청이 실패한다. 시험 비밀 키는 시험용 더미 토큰만 받고 실제 위젯의 토큰은 거절한다. 운영 비밀 키는 더미 토큰을 거절한다. Vercel 로그에는 `waitlist: turnstile mismatch`나 Cloudflare의 오류 코드로 보인다. 위젯은 Managed 모드, 허용 호스트는 `sding.kr` 하나로 만든다.
- Vercel의 환경 변수는 다시 배포해야 적용된다.
- `MEDIA_PREVIEW=off`는 이 PC에서 검증할 때만 쓴다. 검토용 사본이 있어도 포스터 상태로 빌드하고, `next build`와 `next start`에 같은 값을 준다. 호스팅 설정에는 넣지 않는다. Vercel이 스스로 두는 `VERCEL` 변수가 있으면 검토용 사본을 세지 않는다. 검토용 사본의 주소는 `NEXT_PUBLIC_MEDIA_BASE`를 따르지 않고 늘 `/media/preview/`다.

```ts
export function ctaMode(now: Date = new Date()): CtaMode {
  const opened = now.getTime() >= LAUNCH_AT;
  const want = SITE.ctaOverride || (opened ? 'live' : 'waitlist');
  const hasStore = Boolean(SITE.store.ios || SITE.store.android);
  return want === 'live' && hasStore ? 'live' : 'waitlist';

// 날짜 문구는 SITE.launchDate 하나에서만 만든다

export const launchFull = () => { const [y, m, d] = ymd(); return `${y}년 ${m}월 ${d}일`; };  // 2026년 12월 25일
export const launchDotted = () => SITE.launchDate.replace(/-/g, '.');                         // 2026.12.25
```

- 루트 레이아웃(`src/app/layout.tsx`)에 `export const revalidate = 3600;`을 둔다. 헤더 CTA가 모든 페이지에 있으므로 모든 페이지가 같은 주기로 다시 만들어져야 한다. 오픈일 0시(KST) 이후 첫 재생성에서 자동으로 `live`가 된다. 이 방식을 쓸 수 없는 호스팅이면 그 시각에 배포 훅을 호출한다. `public/llms.txt`는 빌드 직전(`prebuild`)에만 만들어 재생성으로 바뀌지 않는다. 오픈일 0시(KST)가 지나면 한 번 다시 배포해 '정식 오픈 예정일'을 '정식 오픈일'로 바꾼다.
- 수동 전환은 `SITE.ctaOverride`를 바꾸고 배포한다.
- 날짜가 들어가는 문구는 `launch.ts`의 도우미로 만들고, 문구에 날짜를 직접 쓰지 않는다. 히어로 날짜 줄과 공유 이미지는 `launchDotted()`, 마지막 CTA 헤드라인은 `launchLabel()`, FAQ 답변은 `launchFull()`을 쓴다.
- CTA 버튼(`CtaButton`)은 `next/link`로 `/#waitlist`를 가리키고, 신청 창은 `onNavigate`에서 연다. `onNavigate`는 일반 클릭에서만 불리므로 Ctrl·Cmd 클릭, 하이드레이션 전 클릭, `dialog`가 없는 브라우저와 JS 끔은 마지막 섹션의 폼으로 이동한다. `data-cta` 속성은 분석 이벤트 `cta_click`이 읽는다.
- `ctaMode()`는 서버 컴포넌트에서만 부르고 결과를 문구와 prop으로 넘긴다. 클라이언트 렌더링에서 `new Date()`를 부르면 자정 전후로 서버 HTML과 달라져 하이드레이션 오류가 난다.
- `live`가 되면 폼 대신 스토어 링크와 QR을 보이고, 헤더 버튼은 '앱 시작하기'로 바뀐다. JSON-LD에는 `MobileApplication` 노드가 더해지고, FAQ는 `faqFor(ctaMode())`로 오픈 후 항목만 남긴다.

### 사전 신청 API

신청은 `POST /api/waitlist` 하나이며, 휴대폰 번호 한 개와 동의 여부만 받는다. 신청 취소도 같은 주소로 `action: 'withdraw'`와 번호만 받는다. 이름과 이메일은 받지 않고, IP는 읽거나 저장하지 않는다.

```ts
// src/app/api/waitlist/route.ts
import { NextResponse } from 'next/server';
import { createClient } from '@supabase/supabase-js';
import { SITE } from '@/content/site';
import { normalizePhone } from '@/lib/phone';
import { TURNSTILE_ACTION, TURNSTILE_WITHDRAW } from '@/lib/turnstile';

// 응답 표와 동작은 PLAN '사전 신청 API'를 따른다. 번호와 요청 본문은 어디에도 남기지 않는다.
// 로그에는 오류 코드와 HTTP 상태만 쓴다. Supabase의 error.details에는 행의 값이 들어갈 수 있다
export const maxDuration = 15;   // 확인 6초와 저장 5초를 넘기면 끊는다. 기본 300초로 두면 폼이 그만큼 기다린다

const CONSENT_VERSION = '2026-11-v6';   // 동의 문구나 처리방침이 바뀌면 올린다
const VERIFY_URL = 'https://challenges.cloudflare.com/turnstile/v0/siteverify';
const VERIFY_TIMEOUT = 3000;
const HOSTNAME = new URL(SITE.url).hostname;

const fail = (status: number, code: string) => NextResponse.json({ ok: false, code }, { status });

// ok: 사람. bad: 토큰이 틀렸다. down: Cloudflare 장애나 키 설정 문제라 방문자 잘못이 아니다
async function humanCheck(token: string, action: string): Promise<'ok' | 'bad' | 'down'> {
  if (!token || token.length > 2048) return 'bad';
  const body = new URLSearchParams({
    secret: process.env.TURNSTILE_SECRET_KEY ?? '',
    response: token,
    idempotency_key: crypto.randomUUID(),   // 다시 보내도 같은 토큰이 '이미 쓴 토큰'이 되지 않는다
  });
  for (let attempt = 0; attempt < 2; attempt++) {
    try {
      const res = await fetch(VERIFY_URL, { method: 'POST', body, signal: AbortSignal.timeout(VERIFY_TIMEOUT) });
      const result = (await res.json()) as { success?: boolean; hostname?: string; action?: string; 'error-codes'?: string[] };
      if (result.success === true) {
        if (process.env.NEXT_PUBLIC_SITE_ENV !== 'production') return 'ok';   // 시험 키의 hostname과 action은 다른 값이다
        if (result.hostname === HOSTNAME && result.action === action) return 'ok';
        console.error('waitlist: turnstile mismatch');   // www로 열렸거나 키 쌍이 어긋났다. 방문자는 다시 눌러도 통과하지 못한다
        return 'bad';
      }
      const codes = result['error-codes'] ?? [];
      if (codes.includes('internal-error')) continue;
      if (codes.some((code) => code.endsWith('-input-secret'))) {
        console.error('waitlist: turnstile secret');
        return 'down';
      }
      console.error('waitlist: turnstile', codes.join());   // Cloudflare의 고정 문자열이다
      return 'bad';
    } catch {
      // 시간 초과나 망 오류. 같은 idempotency_key로 한 번 더 보낸다
    }
  }
  console.error('waitlist: turnstile unavailable');
  return 'down';
}

const client = (url: string, key: string) => createClient(url, key, {
  auth: { persistSession: false, autoRefreshToken: false, detectSessionInUrl: false },
  db: { timeout: 5000 },
});

// 신청 취소(같은 폼). 번호가 있든 없든 같은 답을 준다. 등록 여부를 드러내지 않는다.
// 번호는 rpc 본문으로만 보낸다. Data API에 번호로 거르면 주소에 번호가 남아 게이트웨이 로그에 쌓인다
async function withdraw(body: Record<string, unknown>, url: string, key: string) {
  if (body.hp) return NextResponse.json({ ok: true });
  const phone = typeof body.phone === 'string' ? normalizePhone(body.phone) : null;
  if (!phone) return fail(400, 'phone');

  const human = await humanCheck(typeof body.token === 'string' ? body.token : '', TURNSTILE_WITHDRAW);
  if (human === 'down') return fail(503, 'server');
  if (human === 'bad') return fail(400, 'challenge');

  try {
    // 지운 행이 있으면 함수가 날짜별 건수만 번호 없이 기록한다(파기 기록)
    const { error, status } = await client(url, key).rpc('waitlist_withdraw', { p_phone: phone });
    if (!error) return NextResponse.json({ ok: true });
    console.error('waitlist: withdraw', error.code, status);
  } catch {
    console.error('waitlist: withdraw unavailable');
  }
  return fail(500, 'server');
}

export async function POST(req: Request) {
  const url = process.env.SUPABASE_URL;
  const key = process.env.SUPABASE_SECRET_KEY;
  if (!url || !key || !process.env.TURNSTILE_SECRET_KEY) return fail(503, 'server');

  const body = await req.json().catch(() => null);
  if (!body || typeof body !== 'object' || Array.isArray(body)) return fail(400, 'invalid');
  if (body.action === 'withdraw') return withdraw(body, url, key);   // 동의 검사보다 앞에서 나눈다. 취소에는 동의가 필요 없다
  if (body.hp) return NextResponse.json({ ok: true });       // 봇: 저장하지 않고 성공처럼 답한다
  if (body.consent !== true) return fail(400, 'consent');
  const phone = typeof body.phone === 'string' ? normalizePhone(body.phone) : null;
  if (!phone) return fail(400, 'phone');

  const human = await humanCheck(typeof body.token === 'string' ? body.token : '', TURNSTILE_ACTION);
  if (human === 'down') return fail(503, 'server');
  if (human === 'bad') return fail(400, 'challenge');

  try {
    const db = client(url, key);
    // 이미 있는 번호는 첫 동의를 그대로 두고 조용히 넘어간다. insert로 23505를 받으면 번호가 Postgres 로그에 남는다
    const { error, status } = await db.from('waitlist').upsert(
      { phone, consent_at: new Date().toISOString(), consent_version: CONSENT_VERSION },
      { onConflict: 'phone', ignoreDuplicates: true },
    );
    if (!error) return NextResponse.json({ ok: true });
    console.error('waitlist: db', error.code, status);   // 게이트웨이 오류는 code가 없다. 잘못된 키, 멈춘 프로젝트, 시간 초과는 status로 가른다
  } catch {
    console.error('waitlist: db unavailable');
  }
  return fail(500, 'server');
}
```

```ts
// src/lib/phone.ts
// 화면과 API가 같은 함수를 쓴다(PLAN '사전 신청 API').
// 브라우저 자동 완성은 +821023456789나 1023456789로 넣기도 하므로, 자르거나 검사하기 전에 국내 형식으로 바꾼다
function toNational(raw: string): string {
  const d = raw.normalize('NFKC').replace(/\D/g, '');
  const intl = /^(?:00)?82(\d*)$/.exec(d);            // +82 10…, 82 10…, 0082 10…, +82 010…
  const n = intl?.[1] ? (intl[1].startsWith('0') ? intl[1] : `0${intl[1]}`) : d;   // 82만 친 값은 다음 숫자가 올 때까지 둔다
  return /^10[2-9]\d{7}$/.test(n) ? `0${n}` : n;      // 국가번호와 앞의 0이 함께 빠진 값
}

// 전기통신번호관리세칙 제20조: 이동전화는 010-ABYY-YYYY(A=2~9)
export function normalizePhone(raw: string): string | null {
  if (raw.length > 32) return null;
  const d = toNational(raw);
  return /^010[2-9]\d{7}$/.test(d) ? d : null;
}

// 입력 중 표시용: 010-2345-6789. 자리가 넘쳐도 자르지 않고 그대로 보여 검증에서 막는다
export function formatPhone(raw: string): string {
  const d = toNational(raw);
  return [d.slice(0, 3), d.slice(3, 7), d.slice(7)].filter(Boolean).join('-');
}
```

```sql
-- 새 프로젝트의 표에는 service_role 권한도 없다. 자동 노출 설정과 상관없이 같은 결과가 되도록 직접 정한다

create table public.waitlist_purge_log (
  day date primary key,                    -- 한국 시간 날짜
  n integer not null                       -- 그날 신청 취소로 지운 건수. 번호는 남기지 않는다(파기 기록)
);
alter table public.waitlist_purge_log enable row level security;
revoke all on table public.waitlist_purge_log from anon, authenticated, service_role;
grant select (day, n), insert, update (n) on table public.waitlist_purge_log to service_role;
grant delete on table public.waitlist to service_role;   -- 함수가 부른 쪽(service_role) 권한으로 지운다

create function public.waitlist_withdraw(p_phone text) returns void
language plpgsql security invoker set search_path = '' as $$
declare
  gone integer;
begin
  delete from public.waitlist where phone = p_phone;
  get diagnostics gone = row_count;
  if gone > 0 then
    insert into public.waitlist_purge_log as l (day, n)
    values ((now() at time zone 'Asia/Seoul')::date, gone)
    on conflict (day) do update set n = l.n + excluded.n;
  end if;
end;
$$;
revoke execute on function public.waitlist_withdraw(text) from public, anon, authenticated;   -- 새 함수는 PUBLIC이 실행할 수 있다
grant execute on function public.waitlist_withdraw(text) to service_role;
```

| 상황 | 상태 | 본문 | 화면 문구 |
| --- | --- | --- | --- |
| 정상 신청 | 200 | `{ ok: true }` | 신청이 완료됐어요. 오픈하는 날 문자로 알려 드릴게요. |
| 이미 신청한 번호 | 200 | `{ ok: true }` | 정상 신청과 같다. 번호가 등록돼 있는지 드러내지 않는다 |
| 허니팟이 차 있음 | 200 | `{ ok: true }` | 정상 신청과 같다. 저장하지 않는다 |
| 신청 취소(`action: 'withdraw'`) | 200 | `{ ok: true }` | 번호가 있든 없든 '신청 취소를 처리했어요. 이 번호로 한 신청이 있었다면 목록에서 지웠어요.' 번호 형식 오류, 봇 확인 실패, 서버 오류는 신청과 같다 |
| 번호 형식 오류 | 400 | `code: 'phone'` | 휴대폰 번호를 다시 확인해 주세요. |
| 동의하지 않음 | 400 | `code: 'consent'` | 개인정보 수집·이용에 동의해 주세요. |
| 봇 확인 실패 | 400 | `code: 'challenge'` | 확인에 실패했어요. 다시 시도해 주세요. |
| 요청 전에 Turnstile이 실패함(스크립트 차단, 위젯 오류, 시간 초과) | 요청 없음 | 없음 | 봇 확인 실패와 같다 |
| 본문 오류 | 400 | `code: 'invalid'` | 번호 형식 오류와 같다 |
| 서버·DB 오류, 키 없음, Cloudflare 장애 | 500, 503 | `code: 'server'` | 잠시 후 다시 시도해 주세요. |
| JSON이 아닌 응답(413, 504 등), 망 오류, 20초 안에 답이 없음, 사이트 키 없음 | 그대로, 요청 없음 | 없음 | 서버 오류와 같다 |

- 폼 입력은 `type="tel"`, `inputmode="tel"`, `autocomplete="tel"`로 두고 `formatPhone()`으로 보여 준다. `maxlength`와 `pattern`은 두지 않는다. Chrome 자동 완성은 저장된 형식과 상관없이 `+821023456789`를 넣으므로 자르기 전에 국내 형식으로 바꾼다. 커서가 끝에 있을 때만 바로 다듬고, 중간을 고칠 때는 칸을 떠날 때 다듬는다. 하이드레이션 전에 넣은 번호와 체크는 넘겨받는다. 체크는 `autocomplete="off"`라 브라우저가 되살리지 않아, 기본 해제가 지켜진다.
- 번호는 전기통신번호관리세칙 제20조의 010-ABYY-YYYY(A=2~9)만 받는다. 01X 번호는 서비스가 끝났다. `010-1234-5678` 같은 번호도 오류가 되므로 시험에는 쓰지 않는다. 시험 번호도 실제 가입자일 수 있으니 운영 표에 넣지 않는다.
- 허니팟 칸은 `hidden` 안에 `name="sd_note"`로 둔다. 화면 밖에 두면 자동 완성이 채울 수 있고, 국내 사이트에서 `hp`는 휴대폰 칸의 이름으로 쓰인다. 요청 본문의 키는 `hp`다.
- 폼은 `method="post"`, `action="/api/waitlist"`로 두어 번호가 주소에 남지 않게 한다. 제출 버튼은 하이드레이션 전까지 `disabled`이고, 전송 중에는 포커스가 남도록 `aria-disabled`를 쓴다. Firefox는 새로 고침 때 풀린 `disabled`까지 되살리므로 버튼에 `autocomplete="off"`를 둔다. 같은 이유로 번호 칸은 `readOnly`로 잠그고 체크는 눌러도 바뀌지 않게 한다. 요청은 20초가 지나면 끊는다. 서버 한도 15초보다 길고, 다시 눌러도 번호는 한 번만 저장된다.
- Turnstile 토큰은 300초 안에 한 번만 검증된다. 위젯은 신청 버튼을 누른 폼에서 그 순간 `render()`로 만들고(`appearance: 'interaction-only'`), 토큰을 받으면 `remove()`로 없앤다. 재시도는 새 위젯이 새 토큰을 받는다. 쓴 위젯에 `execute()`를 다시 부르면 이미 쓴 토큰이 돌아온다. 그래서 닫힌 신청 창이나 쓰지 않는 폼에 위젯이 남지 않고, 신청하지 않는 방문자는 확인을 받지 않는다. 스크립트도 폼에 입력을 시작해야 받으므로 지나가는 방문자의 IP는 봇 확인 때문에 Cloudflare로 가지 않는다. 대신 Cloudflare가 권하는 '미리 실행'과 달리 버튼을 누른 뒤에 기다린다. 실기기에서 느리면 입력칸에 처음 포커스가 갈 때 시작하도록 바꾸되, 처리방침의 시점 문구를 함께 고친다. 데스크톱 신청 창은 열 때 입력칸에 포커스가 가므로 창을 여는 것만으로 확인이 시작된다.
- 스크립트(`api.js?render=explicit&onload=…`)는 폼에 처음 입력할 때 한 번만 불러오고, 제출 때 아직 없으면 그때 불러온다. 주입한 스크립트는 `async`가 되어 `turnstile.ready()`를 쓸 수 없다. 복사하거나 프록시하지 않는다.
- 서버는 번호와 동의를 먼저 확인하고 토큰을 검증한다. 잘못된 입력에 토큰을 쓰지 않기 위해서다. 그 전에 DB를 건드리지 않으므로 Cloudflare 튜토리얼의 순서와 달라도 안전하다.
- 번호와 요청 본문은 로그에 남기지 않는다. 오류는 코드와 HTTP 상태만 남긴다. Supabase의 `error.details`에는 행의 값이 들어갈 수 있다. 게이트웨이 오류에는 `code`가 없어, 잘못된 키나 멈춘 프로젝트, 시간 초과(상태 0)는 상태로 가른다. Turnstile은 Cloudflare의 고정 오류 코드와 hostname·action 불일치를 남긴다. `insert`로 23505를 받으면 `Key (phone)=(…)`가 Postgres 로그에 남아 EU로 가므로 `upsert`로 넘긴다. 다시 신청해도 첫 동의 시각과 버전이 그대로다. 이 방식은 `service_role`에 `phone` 읽기 권한이 있어야 해서, 비밀 키가 새면 번호를 읽을 수 있다.
- 이 표의 쓰기와 신청 취소의 삭제는 Data API(`upsert`와 `rpc('waitlist_withdraw')`, 번호는 본문으로만)로 하고, 내려받기와 그 밖의 삭제는 SQL 편집기로 한다. Data API에 번호로 거르면 주소에 번호가 남아 게이트웨이 로그에 쌓인다. SQL 편집기는 입력을 자동 저장하므로 번호를 통째로 적지 않고, 뒤 네 자리로 찾아 `id`로 지운다.
- 문자는 이 저장소에서 보내지 않는다. 오픈 당일 번호를 내려받아 문자 대행사로 보내고 `notified_at`을 채운다. CTA는 0시에 바뀌지만 문자는 08~21시에 도달하게 보낸다. 광고로 처리하면 문자 형식은 '사전 신청의 개인정보' 표를 따른다. 대행사는 전송자격인증 업체여야 하고.
- 보유 기간은 안내 문자를 보낸 뒤 5일 안, 늦어도 2027년 6월 30일까지다. 발송과 실패 재발송을 마친 뒤 보낸 날부터 5일 안에 `delete from public.waitlist;`로 행 전체를 지운다. `notified_at`이 빈 행(발송 실패, 늦은 신청)도 함께 지워진다. 오픈이 늦어지면 2027년 6월 30일까지 같은 문장을 실행한다. 지운 날짜, 건수, 방법, 확인자를 파기 기록에 남긴다. 문자를 보내려고 내려받은 파일은 문자 업체에 넘긴 날 지우고, 업체에 올린 발송 목록도 같은 5일 안에 지우게 한다. 업체가 법령에 따라 보관하는 발송 기록(수신 번호, 발송 일시)은 처리방침의 업체 항목에 그 근거와 기간을 적는다. 프로젝트를 지워도 데이터는 30일 안에 삭제되므로 곧바로 사라지지는 않는다.
- 동의 철회나 삭제 요청은 신청 폼 아래 '신청 취소하기'와 개인정보보호책임자 연락처로 받는다. 취소 폼으로 온 요청은 받은 때 신청 목록에서 지우고, 메일과 전화로 온 요청은 지체 없이 지운다. 지운 행은 백업 보관 기간이 끝날 때까지 백업에 남는다(사실표 7-3, 검토서 P4). 취소 폼은 `{ action: 'withdraw', phone, token, hp }`를 같은 주소로 보내고, 서버는 동의 검사보다 앞에서 나눈다. 허니팟, 번호 형식, Turnstile(action `withdraw`)을 신청과 같은 순서로 확인한 뒤 `rpc('waitlist_withdraw', { p_phone })`를 부른다. 번호는 요청 본문으로만 가서 주소와 게이트웨이 로그에 남지 않는다. 번호가 있든 없든 `{ ok: true }`로 답한다. 운영에서는 action이 맞아야 해서, 신청 토큰으로 취소하거나 취소 토큰으로 신청할 수 없다. 함수는 지운 행이 있으면 한국 시간 날짜별 건수만 `waitlist_purge_log`에 더한다(파기 기록, 번호 없음).

### 분석 이벤트

GA4 이벤트는 7개이며, 모두 `track(name, params)` 하나로 보낸다. GA ID가 없거나 `gtag`가 없으면 아무것도 보내지 않는다.

| 이벤트 | 보내는 때 | 매개변수 |
| --- | --- | --- |
| `cta_click` | 헤더·히어로의 CTA, 마지막 섹션·신청 창의 신청 버튼과 스토어 링크를 누를 때 | `location`: header, hero, final, dialog. `mode`: waitlist, live |
| `video_play` | 영상이 처음 재생될 때(페이지당 한 번) | `media_id`: `MEDIA`의 키(hero, price, planner, dress, hall). 실제 영상만 보낸다. 소개 영상이 오면 소개 영상 창의 재생은 film이고, 히어로 배경 루프는 보내지 않는다 |
| `video_milestone` | 재생이 3초와 25·50·75·100%를 지날 때(영상마다 한 번씩). 반복 재생은 끝에서 처음으로 돌아가는 순간이 100%다 | `media_id`, `mark`: 3s, 25%, 50%, 75%, 100% |
| `video_fallback` | 자동 재생 대신 포스터와 재생 버튼을 보일 때 | `reason`: reduced\_motion, save\_data, low\_power, rejected |
| `feature_view` | 기능 섹션(`section[data-feature]`)의 50% 이상이 보이거나 섹션이 화면 높이의 50% 이상을 차지할 때(섹션당 한 번) | `feature_id`: price, planner, dress, hall |
| `faq_open` | 방문자가 FAQ 항목을 열 때. 질문 줄을 누르면(마우스나 키보드) 다른 확인보다 먼저 그 항목에 표시를 하고, 표시가 있는 열림만 보낸다. 처음부터 펼친 첫 항목, 화면 이동으로 다시 그려진 항목, 찾기로 저절로 열린 항목은 보내지 않는다 | `faq_id`: what, price-rule, planner, dress, hall, when, where, fee, phone |
| `waitlist_submit` | 신청 결과가 나올 때. 요청 전에 막힌 잘못된 번호와 빠진 동의는 `phone`, `consent`, Turnstile 실패는 `challenge`다. 확인 중에 창을 닫으면 보내지 않는다 | `result`: success, phone, consent, challenge, invalid, server |

- 번호와 입력값은 어떤 매개변수에도 넣지 않는다.
- 이벤트 이름은 영문 소문자와 밑줄만 쓴다.
- 코드는 `src/lib/analytics.ts`에 있고, 여러 컴포넌트에 걸친 CTA, FAQ, 기능 이벤트는 `AnalyticsEvents`가 문서에서 듣는다. GA ID가 없으면 스크립트와 이 컴포넌트를 그리지 않고 아무것도 보내지 않는다. 코드는 번들에 남는다.
- '한 번'은 페이지를 다시 불러올 때까지다. 다른 페이지에 갔다가 홈으로 돌아와도 같은 영상과 기능의 이벤트를 다시 보내지 않는다.
- 헤더의 기능 바로가기 클릭은 재지 않는다. v2.0에서 `sound_toggle`을 빼고 `zone_view`를 `feature_view`로 바꿨다. GA의 맞춤 측정기준 `zone_id`는 `feature_id`가 된다(`ga-settings`).
- `gtag` 초기화는 `<head>`의 인라인 스크립트가 맡고, `gtag.js`는 `next/script`의 `lazyOnload`로 로드가 끝난 뒤에 받는다. 그 사이의 이벤트는 `dataLayer`에 쌓였다가 함께 나간다. 스크립트를 받기 전에 페이지를 떠나면 쌓인 이벤트는 사라진다.
- `allow_google_signals`와 `allow_ad_personalization_signals`는 코드에서 `false`로 둔다. `allow_google_signals`는 관리 화면보다 우선하지만 광고 개인화는 관리 화면의 설정도 끈다. `cookie_domain`을 `'none'`으로 두어 `_ga` 쿠키가 미디어 서브도메인으로 가지 않게 한다.
- `form_submit`, `form_start`, `video_progress`, `click`, `scroll`, `page_view`는 GA의 웹 예약 이름이라 쓰지 않는다.
- 이벤트 매개변수는 맞춤 측정기준으로 등록해야 보고서에 나온다. 등록 전 데이터는 보고서에 나오지 않으므로 GA를 켜기 48시간 전까지 등록한다. 첫 공개에는 GA를 켜지 않는다.
- 자동 `page_view`는 주소가 바뀔 때마다 생기므로 앵커 이동도 잡힐 수 있다. 실제 데이터를 보고 관리 화면의 설정을 정한다.
- 처리방침의 자동 수집 장치(쿠키) 항목에 GA4를, 위탁·국외 이전 항목에 Google, Cloudflare, Supabase, 호스팅 업체를 올린다 \[확인 필요\].

### 호스팅과 DNS

첫 공개는 Vercel 한 곳에서 하고, DNS는 레코드를 더하기만 한다. 도메인 등록처와 DNS 위치는 아직 확인 전이며 가비아로 가정한다 \[확인 필요\].

| 호스트 | 종류 | 값 | 비고 |
| --- | --- | --- | --- |
| `sding.kr` | A | Vercel 대시보드가 알려 주는 값 | 루트 도메인 |
| `www` | CNAME | Vercel 대시보드가 알려 주는 값 | `sding.kr`로 301 이동하도록 Vercel에서 설정한다. Vercel이 권하는 'www를 기본으로, 루트를 이동으로' 설정을 고르지 않는다. 그러면 Turnstile의 hostname 확인에서 모든 신청이 실패한다 |
| 그 밖의 레코드 | — | 건드리지 않는다 | 이미 메일을 쓰고 있다면 MX, SPF, DKIM, DMARC와 인증용 TXT를 그대로 둔다 |

- 레코드 값은 Vercel 대시보드가 알려 주는 값을 그대로 넣는다. 프로젝트마다 다를 수 있어 이 문서에는 적지 않는다.
- HTTPS 인증서는 Vercel이 자동으로 발급한다.
- Cloudflare Pages를 고르면 `revalidate`를 쓸 수 없으므로 CTA 전환 절의 배포 훅 방식을 쓴다.
- 배포는 대표가 요청할 때 회사 계정의 Vercel git 연결로만 한다. 검토용 사본(`public/media/preview/`)이 있는 PC에서 `vercel deploy`, `vercel build`, `--prebuilt`로 배포하지 않는다. 그 폴더가 함께 올라가기 때문이다. `.vercelignore`가 그 폴더와 `docs/private`를 막는 예비 장치다.

### 미디어 배포

미디어는 처음에는 `public/media/`에 두고 같은 도메인에서 내보낸다. DNS 변경과 CORS 설정이 필요 없는 가장 단순한 방법이다. 라이선스가 있는 사진과 영상은 버전이 든 이름으로 `public/media/`에 두고 커밋한다. 무료 요금제로 만든 검토용 사본은 `public/media/preview/`에 두며 git에서 빼고 배포하지 않는다. 같은 `immutable` 헤더가 두 폴더에 걸리므로 검토용 사본도 이름에 버전을 붙인다.

```js
// next.config.ts (headers 부분)
const immutable = [{ key: 'Cache-Control', value: 'public, max-age=31536000, immutable' }];

const nextConfig: NextConfig = {
  async headers() {
    return [
      { source: '/media/:path*', headers: immutable },   // 파일명에 버전을 넣어 교체한다
      { source: '/fonts/:path*', headers: immutable },
      { source: '/:path*', headers: [
        { key: 'X-Content-Type-Options', value: 'nosniff' },
        { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
        { key: 'X-Frame-Options', value: 'DENY' },
        { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
      ] },
    ];
  },
};
```

- 영상을 바꿀 때는 덮어쓰지 않고 `hero-film.v2.mp4`처럼 새 이름으로 올린 뒤 `media.ts`의 주소를 바꾼다.
- 이미지는 `scripts/media.mjs`가 원본에서 정한 폭의 AVIF(q60)와 WebP(q82)로 만든다. `--preview`는 검토용 사본을, `--licensed`는 커밋할 파일을 만들고, `--verify`는 커밋된 파일이 빠졌거나 검토용 사본이 git에 들어갔으면 실패한다. 원본을 바꾸면 버전을 올린다.
- 자막 `.vtt`는 `public/captions/`에 둔다. 같은 도메인이면 CORS 설정이 필요 없다.
- MP4는 `faststart`로 내보낸 파일만 올린다.
- 배포 뒤 `curl -I`로 영상의 `Cache-Control`, `Accept-Ranges: bytes`, `Content-Type: video/mp4`를 확인한다.
- `public/media/` 합계가 100MB를 넘거나 영상 교체가 잦아지면 2단계로 옮긴다. 이 기준은 제안값이다.

2단계는 Cloudflare R2에 올리고 `media.sding.kr`로 내보내는 방식이다. R2의 사용자 지정 도메인은 그 도메인이 같은 계정의 Cloudflare 영역이어야 하므로 DNS 이전이나 부분(CNAME) 설정이 필요하다([Cloudflare 문서](https://developers.cloudflare.com/r2/buckets/public-buckets/)). `r2.dev` 주소는 속도 제한이 있어 개발용으로만 쓴다. 옮길 때 코드는 `NEXT_PUBLIC_MEDIA_BASE`만 바꾸면 되지만 처리방침에 Cloudflare 미디어 항목이 나타나므로, 변경 공지와 변경 전후 비교, 시행일, `CONSENT_VERSION`을 함께 챙긴다.

## Claude Code 핸드오프

개발은 새 저장소에 이 기획서의 Markdown 내보내기와 `CLAUDE.md`를 먼저 두고, 아래 8단계 순서로 진행한다. 값이 없는 항목은 지어내지 않고 비워 둔 채 끝까지 만든다.

### 시작 준비

1. 저장소(GitHub `aimbrige-netizen/sding.kr`)를 만들고 Claude Code를 연다.
2. 이 기획서를 Markdown으로 내보내 `docs/PLAN.md`로 저장한다.
3. 아래 `CLAUDE.md`를 저장소 루트에 저장한다.
4. 가진 자료가 있으면 `public/brand/`와 `src/content/company.ts`에 넣는다. 없어도 시작할 수 있다.
5. 아래 시작 프롬프트를 붙여 넣는다.

### CLAUDE.md

```markdown
# 스딩 랜딩페이지 (sding.kr)

주식회사 스딩의 원페이지 랜딩이다. 기획 원본은 `docs/PLAN.md`이며, 이 파일과 충돌하면 `docs/PLAN.md`를 따른다.

## 한 줄 정의
스딩은 웨딩 가격을 정찰제로 투명하게 만들고, AI로 플래닝·드레스·웨딩홀을 미리 경험하게 하는 웨딩 플랫폼이에요.

## 스택
Next.js 14+ (App Router), TypeScript, Tailwind CSS, SSG. 호스팅은 Vercel. 폰트는 Pretendard Variable 자체 호스팅.

## 구조 원칙
- 문구와 값은 `src/content/`에만 둔다. 컴포넌트는 읽기만 한다.
- 색, 간격, 글자 크기는 `src/styles/tokens.css`의 토큰만 쓴다. 헥스 값을 컴포넌트에 직접 쓰지 않는다.
- 페이지는 `/`, `/privacy`, `/terms`뿐이다. 서버 코드는 `/api/waitlist` 하나뿐이다.
- 영상과 이미지는 `MediaSlot`으로만 넣는다. 파일이 없으면 브랜드 포스터 카드를 그린다.

## 하지 않는 것
- 로그인, 가입, 결제, 마이페이지는 만들지 않는다. 라우트도 만들지 않는다.
- `COMPANY.mailOrderNo`(통신판매업 신고번호)는 신고 전까지 빈 값으로 둔다.
- ®는 쓰지 않는다.
- 법인명은 '주식회사 스딩'만 쓴다. 다른 회사나 서비스 이름을 섞지 않는다.
- 후기, 평점, 수상, 고객 수, 금액, 할인율처럼 근거 없는 주장을 만들지 않는다.
- 모르는 값은 빈 값과 `TODO(항목)` 주석으로 두고 `docs/OPEN_ITEMS.md`에 적는다.
- 다크 모드, 외부 애니메이션 라이브러리, 회색 자리표시 박스, '준비 중' 문구를 쓰지 않는다.
- 소리를 기본으로 켜지 않는다. 영상은 무음으로 시작하고, 소리는 방문자가 소개 영상 창의 컨트롤로 켤 때만 난다. 소리 상태는 저장하지 않는다.
- 레퍼런스 사이트의 문구, 이미지, 영상을 복사하지 않는다.
- 번호와 입력값을 로그와 분석 이벤트에 남기지 않는다.
- 무료 요금제로 만든 이미지와 그 파생 파일은 커밋하지 않는다(로컬 커밋 포함). 검토용 사본은 git 밖의 public/media/preview/에만 둔다.
- 이 PC에서 vercel deploy, vercel build, --prebuilt로 배포하지 않는다. 배포는 대표가 요청할 때 회사 계정의 git 연결로만 한다.

## 명령
`npm run dev`, `npm run build`, `npm run lint`, `npm run typecheck`

## 끝났다고 하기 전에
build, lint, typecheck가 통과해야 한다. `docs/PLAN.md`의 '성능과 접근성 기준'과 '측정과 출시 점검' 표를 확인한다.
```

### 시작 프롬프트

```text
docs/PLAN.md와 CLAUDE.md를 먼저 끝까지 읽어 줘.
그다음 PLAN.md의 'Claude Code 핸드오프' 절에 있는 작업 순서대로 1단계부터 만들어 줘.

진행 방식:
1. 한 단계가 끝날 때마다 build, lint, typecheck를 돌리고, 통과하면 커밋해 줘. 커밋 메시지는 한국어로 짧게 써 줘.
2. 값이 없는 항목(로고 SVG, 전화번호, 이메일, 개인정보보호책임자, 영상 파일, SNS 주소, 스토어 주소)은 지어내지 말고, 빈 값과 TODO 주석으로 두고 docs/OPEN_ITEMS.md에 적어 줘.
3. 영상과 이미지 파일이 없으면 MediaSlot이 브랜드 포스터 카드를 그리게 해 줘. 회색 박스나 '준비 중' 문구는 쓰지 마.
4. 기획서와 다르게 하고 싶은 부분이 있으면 코드를 바꾸기 전에 먼저 말해 줘.

지금은 1단계만 하고, 끝나면 만든 파일 목록과 확인한 결과를 알려 줘.
```

| 7. 분석과 점검 | `analytics.ts`의 이벤트 7개, Lighthouse, 접근성, 테스트 매트릭스 | 이벤트 7개가 나가고, 자동 접근성 검사가 기준을 넘는다. Lighthouse는 로컬에서 재서 `docs/OPEN_ITEMS.md`에 기록하고, 기준은 배포 미리보기에서 확인한다. INP, 실기기, 영상이 필요한 항목도 그 파일의 날짜에 확인한다(SEO는 첫 공개 당일 `sding.kr`에서 잰다) |

### 완료 기준

- `build`, `lint`, `typecheck`가 모두 통과한다.
- 성능과 접근성 기준 표, 테스트 매트릭스를 모두 통과한다.
- 페이지 소스에 정의 문장, `h1` 하나, canonical, OG 태그, JSON-LD가 있다.
- 푸터의 통신판매업 신고번호는 빈 값이고, 사업자등록번호와 주소는 사업자등록증과 같다.
- 로그인·가입·결제 화면과 라우트가 없다. CTA 설명의 '로그인은 필요 없어요'와 약관의 '결제를 받지 않아요'처럼 없다고 밝히는 문구만 예외다.
- 번호가 로그와 분석 이벤트에 남지 않는다.
- 소리는 방문할 때마다 꺼진 상태로 시작한다.
- `docs/OPEN_ITEMS.md`에 남은 항목이 이 기획서 처음의 확정 필요 목록과 맞는다.

### 기획 변경과 열린 항목

기획이 바뀌면 이 문서를 고치고 `docs/PLAN.md`를 다시 내보낸다. 코드를 만들다 생긴 질문은 `docs/OPEN_ITEMS.md`에 적고, 답이 정해지면 이 문서에 반영한다.
